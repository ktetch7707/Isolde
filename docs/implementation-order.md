## Codebase assessment

The existing Qt/C++ application is the foundation to extend. `ProfileRuntime` creates profile-scoped catalog, layout, session and Kodi objects; audio remains device scoped. `SessionManager` handles installed-app sessions, while `KodiMedia` and `KodiService` coordinate managed playback and native frontend ownership. The private local bridge, read-only media grants and native/browser isolation already have substantive tests. Keep those boundaries and supported Kodi APIs.

Backend ownership clarification: Kodi owns source scanning, movie/show/season/episode organization, metadata, artwork acquisition/cache, watched and resume records, decoding, playback and audio/subtitle track handling. Isolde queries and controls those capabilities through supported Kodi APIs. Its work is presentation, remote navigation, bounded request adaptation, profile/session coordination and focus/return behavior. Do not build a parallel media database, scraper, artwork downloader, progress tracker or player. Any Isolde-side display cache must be disposable and derived from Kodi; it must not become a second source of truth.

`HomeLayout` is a version-1 tile/category layout, not yet the planned general component tree. `KodiShelves` projects named movie-rule collections into Home and now also exposes TV-show rule collections through a validated open-show action. The show extension has regression coverage in source but still needs an installed remote-only and real-Kodi acceptance run. Do not reimplement the existing movie shelf behavior.

The principal architectural bottleneck is shared presentation/source/action configuration: collection queries, generated Home tiles and action dispatch are currently coupled to movie-specific paths. `KodiMedia` also combines transport, paging, collection persistence, scan and playback state. Extract shared definitions incrementally when a second consumer needs them; a wholesale rewrite would delay a working product. `Main.qml` owns global shortcuts and dispatch; new overlays must preserve input precedence and profile teardown.

The documentation is uneven: README still describes a mock-only prototype, and older plan sections prioritize packages even after later Kodi work. Current source and dated verification entries are the baseline. Much of the repository is already modified/staged/untracked; preserve that work and avoid cleanup or unrelated formatting.

## Delivery rules

- Finish vertical slices: remote input → data → visible result → error/retry → restored focus. Backend-only completion does not close a product feature.
- Reuse source/collection adapters across shelves, tabs, search and guide. Keep collection definitions independent of where they are displayed.
- Every persistence change needs compatible loading, bounded validation and preservation of existing user data. Never modify Kodi databases or reorganize media.
- Run relevant automated suites at each slice. Require actual installed UI acceptance for navigation/presentation claims and physical hardware for audio, capture, CEC and latency claims.
- Keep offline/local operation, account isolation and recoverable Settings access working throughout. Do not add online providers before local-only request boundaries are tested.

## M3 — Page editor/renderer visual (Isolde Studio M2 follow-up)

Page-scoped `grid`/`placements` are now wired to `PageSurface` via `PageModel` instead of root-level `configuration`. M3 builds the visual page editor/renderer on top of this foundation:

- **Page editor surface**: per-page grid/placement editor in `CustomizeHomeView`, bound to `PageModel.grid`/`PageModel.placements` through `PageSurface`; supports drag-to-place, snap-to-grid, resize and remove for page items.
- **Page renderer**: `ComposedHome` renders page items against `PageModel.grid`/`PageModel.placements`, applying per-page `appearance`, `wallpaperSource`, `tileRoundness`, `brandVisible` and `backgroundStart`/`backgroundEnd`.
- **Page skin persistence**: per-page grid/placements included in skin save/apply through `PageModel.storePage()`/`loadDocument()`; skins preserve page-scoped layout independently of root configuration.
- **Tests**: `tst_components.cpp` `pagesPersistAndRouteAndTravelWithSkins` updated to cast `pageModel()` to `PageModel*` (grid/placements/setAppearance/addWidget paths); grid/persistence regression coverage added.

Depends on M2 page-scoped `PageModel` composition (this document's prior section). Blocks M4 (universal search integration with page-scoped sources).

## M4 — Universal search integration with page-scoped sources

Command Center now searches page-scoped library sources in addition to the profile-local Kodi titles and saved collections. `PageModel::pageSearchSources()` exposes each page's library sections and library widgets (`presentation.variant == "library"`) as `{id, name, kind, view, value}`. `CommandCenter.qml` accepts `pageId`/`pageSources`, surfaces matching page sources as searchable entries, and emits `pageSourceRequested(pageId, sourceId, kind, view, value)` on activation; `Main.qml` populates page context through `openSearchFromPage()` (used by Home, PageSurface and the `/`/`S` shortcuts) and routes a page-source selection back to the originating page. Search stays local-first and issues no external requests. Regression coverage is in the component suite's `pagesPersistAndRouteAndTravelWithSkins`.

Depends on M3 page-scoped `PageModel` composition. The consolidated [unified master plan](unified-master-plan.txt) (Section 13) refines this further with a persisted Web ON/OFF search toggle and title-detail/viewing-options flow; those are future slices that require a verified discovery backend before any Web ON path is wired.
