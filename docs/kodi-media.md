# Local Kodi front end — development preview

## Television, recent items and artwork — October 16

Movies and Shows now share a remote-operated library. Shows → seasons (including Specials) → episodes supports paged navigation, direct play/resume and restart from details. Back restores the parent page and selected row. Movies/Shows can be selected from the toolbar; existing custom Home layouts remain intact. Recently Added and Continue Watching query Kodi's date-added, in-progress and last-played data for movies or episodes. Title search follows the current media type. Saved title/tag/genre rules can target Movies or TV shows; show Home shelves expose matching show cards and revalidate membership before entering a show. The Command Center now searches movie, TV-show, and episode titles across these types; playlists, tag-result search, and episode collections remain later work.

The private bridge uses supported `VideoLibrary.GetTVShows`, `GetSeasons`, `GetEpisodes` and item-detail APIs. Managed episode playback uses Kodi episode IDs and explicit resume intent, with the same pause, seek, stop and Home lifecycle as movies. Control ownership checks both media type and ID. Kodi owns library records, watched/resume state, decoding and playback.

Selected-item artwork comes from Kodi-reported local files or its existing thumbnail cache through `Textures.GetTextures`. Isolde performs no artwork downloads. Identity-only artwork requests, bounded regular-file reads, image validation, cancellation and placeholders keep broken or unavailable art independent of browsing. No second media database or progress tracker is introduced.

Automated verification: all thirteen CTest suites pass, covering TV hierarchy, Specials, parent-page restoration, recent/in-progress mapping, cancellation, profile teardown, episode ownership/control, bounded artwork and actual QML navigation/restart. `tools/tv-library-acceptance.py` is the opt-in real-Kodi check: it creates new synthetic media and a disposable profile, imports through Kodi's native settings dialog, then exercises Isolde using window-targeted remote keys. It hashes the fixture files and restores the normal service. It never edits a Kodi database or copies the user's profile. Silent synthetic video does not qualify audio, subtitles, hardware decoding or arbitrary codecs.

Staged live acceptance passed at `/tmp/isolde-tv-acceptance-2hnp_86m`: real Kodi returned one show, two seasons (0 and 1), three episodes and the local poster; remote keys opened an episode, paused it, stopped it and returned through the hierarchy. Fixture media/artwork/import files retained their SHA-256 hashes. The fixture sets its new show's poster through Kodi's supported API after native import. Early harness attempts failed on native-dialog setup, incomplete export XML and artwork naming; those attempts are not passes.

Deployed release `730331857395646ccfc3bc91` passed all thirteen suites during installation and repeated the same real-Kodi acceptance against the installed executable. Evidence: `/tmp/isolde-tv-acceptance-m986n9dt/result.json`, `shell.log` and `artwork.png` (or `.jpg`); installer log `/tmp/isolde-order-vsDgGY/tv-install.log`. ## Search, collections and Continue Watching — October 16

Deployed release `2b11847a5219ae7d22a3c0cf`: all ten suites passed during installation. Normal Isolde service restarted successfully with startup enabled; disposable acceptance settings were not installed into Household.

Movies has All movies, Continue Watching, Search, Collections, Save view and Refresh controls. Up above the first movie focuses the toolbar; Left/Right selects a toolbar action (or changes movie pages while the list is focused). Search uses the existing remote-operated keyboard. It searches local movie titles across the full Kodi library, not just the current page. There is no web-search dispatch or cached web result path. The visible Web OFF label is informational; online search is not implemented.

Continue Watching reads Kodi's `inprogress` rule, ordered by last played. Kodi remains authoritative for resume eligibility. Playback stop reloads the active shelf after Kodi saves state. A shortened final page safely falls back to page one.

Collections → New Kodi tag view / New genre view accepts an exact tag/genre. Search provides a title-contains view. Save view names one of these reusable definitions. Collections can be opened, renamed or removed with explicit removal confirmation. Definitions live in Isolde's per-profile Collections settings, versioned under `v1`; they do not edit tags, reorganize files or remove Kodi records. Multiple definitions may match the same movie. Maximum 64 collections; names 80 characters, filter values 160.

Acceptance: automated paging/filter/profile persistence/cancellation/boundary tests; real Kodi queries against four synthetic movies found the expected title, tag, genre and one in-progress movie, and returned zero matches for missing terms. A remote-only on-screen keyboard sequence saved a named collection in the disposable profile. One screenshot checked the toolbar and Continue Watching layout. ## Manual movie and TV-show collections — October 17

From a movie or TV show's details, Menu opens a remote-operated curation flow. Users can create a named manual collection from that item, add it to another same-type collection, or remove it. Definitions store ordered Kodi IDs in the active Isolde profile; duplicate IDs, unsafe/nonpositive IDs, and lists over 256 are rejected. Kodi metadata and media paths are never modified. Opening a manual movie collection hydrates members through the bridge's bounded read-only `VideoLibrary.GetMovieDetails`; TV-show collections use `VideoLibrary.GetTVShowDetails`. Requests are sequential, paged by 50, and stale IDs are skipped and reported. Manual collections can be pinned as Home shelves: movie members retain validated direct playback, and show members use a validated `open-show` action into Seasons. Automated fake-Kodi coverage exercises create/add/deduplicate/open/remove/persistence and Home shelf actions; live Kodi acceptance remains pending.

## Universal local search — October 17

The global Command Center now debounces a two-character query to three profile-scoped Kodi clients: Movies, Shows, and Episodes. Each uses Kodi's title-contains filter and bounded 50-item pages; previous/next result rows page each type independently. Selecting a movie or episode uses Kodi's existing direct local playback route. Selecting a show reopens the exact search page and verifies the TV-show ID before entering Seasons. Saved collection names are also searchable and open their stored local rule. Kodi-unavailable and in-progress states are visible. Closing the overlay cancels the clients, and the originating Home, page, or library remains underneath. Search issues no web, metadata-provider, or third-party requests; Web is explicitly shown as OFF.

Automated bridge coverage checks Kodi's episode title filter, show-result membership/navigation, and queued playback during a primary-client read. An offscreen remote-search test drives Command Center against a fake local bridge and verifies Movie/Show/Episode results and show-result dispatch. Native tests and installed remote-only/real-Kodi acceptance have not been run in the current Windows environment because CMake/CTest are unavailable. Search results currently cover titles and saved rule names only: tag/playlist result adapters and optional Web ON remain open. Manual movie membership is implemented; show manual membership and exclusions remain open.

## Local playback — October 16

Installed release: `2533073a08b0d78fc0bc5851`. All ten suites passed at installation; the added service callback regression also passed in the seven-test playback suite. The normal user service was restored and restarted after disposable-profile acceptance. One final screenshot verified actual Isolde Home after the remote Home command; screenshots were otherwise limited during the resumed run.

Movies → OK plays/resumes immediately. Menu (or right-click) opens details; Right in details starts from the beginning. During fullscreen playback, OK/Space pauses, Left/Right seeks, Back stops and returns to the library, and Home stops and returns Home. Natural completion returns to Isolde. Kodi owns playback and resume/watch updates; media files are never rewritten by Isolde. Refresh the library to reload updated metadata.

The private bridge accepts an existing library movie ID plus an explicit resume boolean, rejects arbitrary paths/URLs and unavailable non-local media, refuses an already active player, and verifies movie ownership before controls. Startup has a 20-second bound. Home during startup is remembered until the owned player appears. Transport loss reports uncertainty rather than claiming playback stopped. Presentation failures request stop and leave an actionable status.

Managed mode uses an ephemeral read-only keymap overlay; native-mode keymaps are not overwritten. Kodi Python callbacks must be pumped via Monitor.waitForAbort for key notifications. On the qualified VM, managed Kodi uses XWayland; a bounded helper identifies exactly one Kodi window, shows it fullscreen, or minimizes it on return. This is not compositor-independent support. Multiple Kodi windows are rejected for presentation, and no native Wayland activation is claimed.

Acceptance: ten automated suites, real synthetic fullscreen video, OK → paused and Home → ended/home true via actual guest keyboard input. Earlier attempts caught the wrong sandbox keymap target and missing callback processing; those attempts were failures, not passes. The synthetic video is silent: no new speaker, surround, subtitle, HDR, DRM, network-source or arbitrary-codec claim is implied. Existing desktop Kodi migration and full customized-skin qualification remain open. Historical preview limitations below are superseded only by this explicitly scoped playback slice.

## Frontend selection and preservation

Isolde-owned **Settings → System → Media Library** and **Media folder access** surfaces follow the active profile's saved background, surface, selected-surface, focus, text, muted-text and corner-roundness values. This only changes Isolde presentation; opening **Kodi application** still uses the user's native Kodi skin, and Isolde never rewrites Kodi skin settings to imitate its theme.

Settings → System → Media Library now remembers **Isolde (preview)** or **Kodi application** separately for each user. Both use the same profile-private `native-profiles/<id>/kodi/home`; the mode setting lives in Isolde's settings, not Kodi's skin or library configuration. Kodi application mode pauses background auto-start without erasing the user's auto-start preference. Use **Open Kodi with your existing setup**, exit Kodi normally, then switch back here. Ctrl+M routes to Kodi in application mode. This is not yet automatic boot directly into Kodi's skin.

A mode switch asks the bridge to check active players and video/music scans, then requests Kodi's supported Application.Quit. Only a normal process exit commits the mode; rejection or a 20-second deadline leaves it unchanged, without force-killing Kodi for the switch. Launch guards prevent foreground handoff while managed Kodi still owns the home; both launch paths share an ownership lock. Existing application-exit/profile-teardown crash-containment paths are separate and still have bounded forced cleanup; seamless playback handoff is not claimed.

October 15 acceptance: nine automated suites passed during implementation. `isolde_kodi_frontend_smoke` uses a new disposable profile only, non-default maroon Estuary colors, sources/favourites/keymap/add-on-settings fixtures, a normal native Kodi F12 exit, and a second managed start/clean exit. The corrected run preserved fixture bytes and color/skin preferences; the maroon native interface was visually inspected. An earlier Estouchy fixture was invalid because that skin's files were absent, exposing why preference text alone is insufficient. It is not counted as a pass. Arbitrary third-party skins, add-ons, watch/resume state and the user's actual curated setup still need acceptance coverage.

**Existing desktop Kodi is not automatically imported.** It can have a different home than Isolde's isolated profile. No existing desktop setup was copied, overwritten, or reset. A backed-up explicit migration workflow remains required before claiming preservation of a pre-Isolde installation.

Priority: Isolde is the browsing/front-end interface; Kodi and local media live on the same dedicated computer. Kodi retains library management, playback, resume/watch state, and optional add-ons. No separate media server is required. Dedicated appliance installation is prominently deferred in the main development plan, not marked complete.

Deployed browsing acceptance: release `934c5bf1d531506eb8e14d3a`, all nine suites passed. The actual Household Home Movies tile opened the real Kodi-connected empty-library screen. Paging across 103 movies and metadata handling were covered with a simulated local bridge; populated details and large real-library navigation still need visual acceptance. No media was added to Household for this check.

- `kodi/service.isolde.bridge`: Linux Kodi service add-on calling the supported `xbmc.executeJSONRPC` API. It opens a filesystem UNIX socket at `special://profile/isolde/rpc.sock`, **not** a TCP/HTTP listener. Directory permissions are 0700, socket permissions 0600, and Linux peer UID is checked. It refuses unrelated files and duplicate live listeners, recovers stale sockets, limits request size/time, bounds library pages, and allowlists read-only methods.
- `src/media/KodiMedia`: asynchronous Qt local-socket client, three-second deadline, request-ID validation, response-size limit, API-major compatibility gate (13), and a first ten-movie query. Each profile runtime gets its own client/socket path; runtime destruction closes the connection. Credentials are unnecessary for this filesystem transport and are not exposed to QML.
- `qml/KodiLibraryView.qml`: early Isolde library preview. **Ctrl+M from Home** opens it; Enter refreshes, arrows browse, Back returns. Shows an honest empty/offline/error state. Existing user tile actions and Open Kodi are unchanged. This is not yet the final remote-discoverable Movies entry.

The UNIX socket path inside Kodi's sandbox and the host-side path refer to the same profile-private filesystem object. The Qt client opens its directory and connects through `/proc/self/fd/<fd>/rpc.sock` to avoid Linux's short UNIX pathname limit. This still is not an adversarial boundary against another program running as the same OS user; it prevents LAN exposure and preserves the existing profile storage model.

Kodi 21.3's native HTTP server starts listeners without a loopback-only bind in its upstream implementation. Do not enable it assuming that a localhost client URL restricts its listener. This bridge leaves that server disabled. References: [Kodi HTTP implementation](https://github.com/xbmc/xbmc/blob/21.3-Omega/xbmc/network/WebServer.cpp), [Kodi service add-ons](https://kodi.wiki/view/Autoexec_Service), [JSON-RPC API](https://kodi.wiki/view/JSON-RPC_API).

## Verification and boundaries

October 15 scan slice: Settings → System → Media Library now exposes **Scan for New Movies** and connection refresh. The bridge permits `VideoLibrary.Scan` only with empty caller parameters, translating this to `showdialogs: false`; arbitrary directory overrides, cleaning, and other write methods remain forbidden. `XBMC.GetInfoBooleans` permits only `Library.IsScanningVideo`. Kodi updates its own library, without Isolde moving or renaming media files. All configured video sources are scanned, potentially including television sources.

The client polls once per second, reports completion only after observing scanning then idle, and otherwise explicitly reports accepted/idle after five checks. It refreshes the movie preview afterward. Monitoring is bounded to 30 minutes; leaving Settings does not cancel Kodi's scan. Service/profile invalidation cancels client monitoring and queued callbacks. Tests cover rejected scans, duplicate requests, observed completion, unobserved short scans, cancellation, and bridge parameter restrictions. All eight suites passed in the VM; `isolde_kodi_startup_smoke <test-profile-uuid> --scan` also passed with real Kodi in an empty isolated test profile. The deployed button was exercised visually in Household. Neither check proves discovery of a real movie.

### Remembered media folders

Settings → System → Media Library → Media folder access provides remote-operated directory browsing and per-profile read-only permissions. Switch to Kodi application mode and exit Kodi normally before changing access. Select an allowed folder twice to revoke it. Grants apply to both frontends at the original paths, not to other users or applications. Missing drives are skipped without deleting library records. System/private directories, whole home/storage roots, and symlink redirection are refused. No media or Kodi database/source configuration is rewritten by granting or revoking access.

First-time setup still uses Kodi's own Videos → Files → Add videos / Set content UI: select the allowed collection, Movies, recursive scanning, and the preferred scraper (or Local information only for matching NFO files). Existing configured sources need not be recreated. Return to Isolde mode and use Scan for New Movies for subsequent additions. See [Kodi source configuration](https://kodi.wiki/view/Adding_video_sources).

### Managed startup (October 2026)

`KodiService` now starts installed Kodi automatically after setup completes, using the active profile's isolated native home. Settings → System → Kodi startup offers a remembered per-profile switch, status, and retry. A disposable read-only namespace overlay adds the bridge to Kodi's bundled system add-ons; Kodi discovers/enables it through its own lifecycle. Isolde does not edit Kodi's add-on database or the system installation. The bridge minimizes managed Kodi once ready. A brief startup window may still be visible. Currently this requires the Ubuntu `/usr/share/kodi` packaging layout.

Startup probes are bounded to 30 seconds; errors remain visible instead of causing a restart loop. A per-home lock prevents duplicate managed instances. Opening Kodi as a foreground app suspends management; returning Home resumes it. Profile teardown stops the managed process and its descendants before the next profile starts. Automatic startup defaults on, but does not install Kodi or grant access to media files.

`tools/kodi-startup-smoke.cpp` verified fresh-profile and repeat startup against real Kodi without F8 or manual add-on activation. All seven CTest suites passed, including per-profile startup preference persistence. The older F8 probe remains developer scaffolding only. Playback and signed-in isolation acceptance are not implied by these startup checks.

Deployed VM acceptance: Settings Off removed the Kodi process while Isolde stayed active; On persisted and launched a new process. Household → alex → Household replaced each outgoing Kodi process, with alex using its own sandbox home. The final screen was visually checked as Household Home. Live testing caught and fixed a missing QSettings organization and restored Isolde keyboard focus after managed Kodi minimized. Foreground Kodi handoff and crash/read-only-preview stale-state behavior still need dedicated acceptance coverage.

Next: provider-controlled play/pause/stop and focus restoration; posters/pagination/Continue Watching; remote-accessible Movies entry. Playback methods intentionally remain disabled until their lifecycle is implemented. No movie playback, poster rendering, automatic crash-reconnection loop, signed-in switching, or PseudoTV integration is claimed by this slice.
