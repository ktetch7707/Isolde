AUDIT OVERRIDES — 2026-10-19
This consolidated source contains conflicting proposals, not verified implementation facts. docs/agent-backlog.md controls work; docs/planning-audit.md records conflicts. These overrides govern the retained source excerpts:
- Limits: 64 pages/profile; 4 MiB layouts, 1024 components, 128 categories; grids 4–16 columns by 3–10 rows. Unlimited means flexible within validated bounds, never unbounded allocation.
- Kodi owns media metadata, artwork, watched/resume and playback. A future SQLite schedule store owns schedules only; media references/caches are disposable Kodi-derived data, never a second canonical media/progress database.
- T02 curation expansion is out of scope. Existing movie/show manual collections remain as-is. Users curate through Kodi.
- Tabs and destinations are editable presets, not permanent mandatory pages. Profile isolation follows the existing runtime; family layout presets are not security controls.
- Capture currently uses Qt Multimedia/SerialPort. GStreamer installation/health checks do not prove a separate capture pipeline, backend isolation or hardware readiness.
- Web OFF excludes external discovery requests/results. Web ON is an unavailable stub; provider decisions and runtime network-denial acceptance remain open.
- No parallel schema files or code in layouts. Reject unknown versions/types. Preserve v1 read compatibility and atomic v2 writes with backup.

ISOLDE
Unified Master Planning Document
Version 0.0.1.1  •  Consolidated 18 October 2026
Product requirements, system architecture, interface configuration, integration contracts, implementation notes, test criteria, and all supplied visual references.
Non-negotiable product direction
Everything is configurable. Nothing requires configuration.
Isolde is a local-first, offline-capable, remote-first personal entertainment operating environment. A default experience must be polished and ready to use, while its pages, tabs, regions, shelves, menus, launcher tiles, and content sources are completely rearrangeable.
When two source specifications prescribe different layouts or integrations, neither is discarded. Both become selectable templates, modes, widgets, data adapters, or per-page settings, so long as they can coexist safely. A user can select a preset and then change every part of it.
The content catalog is separate from playback sources and separate from UI layout. Titles, access entitlements, local files, channels, games, shelf definitions, and page definitions must not be rigidly coupled.
Offline core functionality does not depend on a service, account, online time server or cloud lookup. Optional apps, provider integrations and metadata enrichment enhance but cannot disable the core experience.
Implementation limitations are identified explicitly; where a provider, HDMI device, capture adapter, PVR add-on or game launcher exposes an unverified capability, treat it as a tested integration requirement rather than a promise.
How this document is organized
Part I specifies shared decisions and makes formerly conflicting approaches configurable. Part II retains the complete technical substance of every supplied planning file in topic order, including every embedded source image and the original Kodi code and project tree. Source headings, tables, examples, phases, and acceptance criteria remain available for implementation detail.
Part I — Unified configuration contract
1. Page system, navigation and defaults
Provide an editable page registry with unlimited user-created pages, arbitrary named tabs, sidebars, top navigation, contextual menus, custom landing pages and deep links. Pages can be duplicated, exported, imported, reordered, hidden, assigned icons and designated as Home. Every page can hold any compatible widget; no predefined category is mandatory.
Ship multiple included templates, at minimum: (A) compact one-screen source launcher with Home, Library, TV Guide, Music and Games; (B) scrollable dashboard with HDMI, apps, On Now, Continue Watching and library shelves; (C) poster-led left-sidebar media library; and (D) user-designed minimal, pastel, or image-background variants. The five-tab navigation is a default template, not a system limit.
Allow per-page vertical scrolling on/off, fixed-height versus content-driven layout, grid rows/columns, widget spanning, responsive spacing, sidebar collapse rules, background art/video/GIF, focus behavior and remote-safe transitions. A single-screen Home and a scrolling Home are both fully valid.
Search and Settings may appear in a persistent header by default but must also be routable as normal actions/buttons/menus. All Apps, Desktop, and every HDMI input must be reachable without reliance on a specific default layout.
2. Widget builder and look-and-feel
Provide editable reusable widgets: HDMI source tile/grid; app launcher; action button; menu sidebar; top tabs; breadcrumb/quick navigation; media shelf; poster grid; collection; hero/banner; guide preview; full/overlay guide; clock/date; weather; now playing; device status; background art/video/GIF; music library; games library; search; settings shortcut; achievements; provider availability and recording widgets.
Each widget exposes its supported source, query/filters, sort, item limit, card density, grid spans, alignment, geometry, visual skin, artwork, text, focus/hover/selection effects, input actions, transitions, visibility conditions and destinations. Action bindings support navigating to pages, opening apps, switching inputs, playing media and invoking supported context panels.
Users can approximate different streaming-service or Kodi-skin layouts with the editor, but no copyrighted art or specific protected assets are necessary. Templates are starting points. All pages, not merely Home, must be editable. Preserve a live preview, undo/revert, backup/export, restore-default and keyboard/mouse-assisted editing alongside remote-first use.
Typography, theme colors, icons, accents, circles/rectangles, posters/landscape art, backgrounds, animations, live wallpapers and screen-reader/focus accommodations must remain theme-level or per-widget settings rather than hardcoded appearance decisions.
3. Catalog and content availability
Maintain one canonical title/media record with multiple playback/access paths. “My Library” (user-controlled compatible local media) and “Borrowed” (external subscription/provider dependent access) are filters and classes, NOT mandatory pages. Users can combine them into one shelf or separate them by page, category or source.
Prefer playback of local material when configured. Offline or lost-entitlement Borrowed titles automatically leave dynamic playable shelves without erasing history, user collections, bookmarks or metadata; they reappear when available again. Show accurate access states on demand rather than pretending streaming licenses equal permanent ownership.
Curated and rules-driven shelves may overlap across sources, genre, tags, franchise, console, language, availability, studio, metadata and service. Do not require a user to organize files or adopt any preset hierarchy. Search supplements browsing rather than replacing intuitive navigation.
Proactive recommendations may use local content and titles included in already-active subscriptions in the user’s normal authorized region, not promoted new subscriptions or retail purchases. Explicit title searches may show other services, rents, purchases, and relevant geographic differences as neutral facts, not ads or VPN guidance.
4. Live television choices and persistence
Provide a configurable unified EPG integrating local Isolde-generated channels, Kodi/PVR or existing PseudoTV channels, compatible IPTV/XMLTV, tuners, and authorized connected provider listings where supported. A user can choose Isolde’s guide, native Kodi guide, an overlay, a compact widget, or provider app handoff.
Isolde-generated local channels use a persisted broadcast clock and schedule database, with configurable real-time, pause-when-off, fixed broadcast and shuffle rules. Keep committed slots stable when folders/rules change, and tune into the elapsed program rather than restarting each show.
Retain imported PseudoTV definitions and their own schedules rather than automatically transferring ownership. Where an Isolde-native channel engine supersedes a PseudoTV workflow, this is an optional channel-source mode, not destructive migration.
The full guide must offer Add Channel → Local/Service, playlist rule editor, scheduling, channel editing, logos, guide filters and remote navigation; guide reads should never require expensive global indexing.
5. Players, HDMI, apps, VPN, downloads and games
Kodi remains a supported media backend and native interface/skin option. Users can open Kodi screens or add-ons as routes within Isolde; a managed full-screen window is the pragmatic default where embedding is unsupported. Isolde UI and Kodi UI are user-selectable browsing modes, not mutually exclusive universes.
Keep eight configurable HDMI inputs plus Desktop as available controls. Switching, capture, controller support and HDCP-protected hardware behavior must be separately validated. Never make the OS dependent on a live network. During external HDMI sessions or normal playback, prevent idle screensavers from interrupting content.
Optional Linux apps (including FreeTube and Parabolic), favorite launchers, installed PC games and emulators integrate through adapters. Files imported through watched folders stay user-accessible, are indexed only when complete, and can power shelves and TV channels.
Games share the same configurable shelf/catalog patterns as movies, with platform, franchise, edition, tag and launcher profile filtering; save metadata and local launch behavior remain offline-capable.
Optional VPN settings can support multiple providers, a user-selected default policy, per-app override/never-use rules, preferred ordered servers, configurable auto-retry, and an app-side quick-control panel. VPN routing does not change the rules for proactive recommendations or circumvent service access requirements.
6. Security, data resilience and implementation
Local SQLite is the suggested canonical metadata/schedule registry, using stable media identities, incremental ingestion, cached artwork, backed-up configuration and schema migration. Source services, UI state, collections, assets, channel schedules and app connectors are separate modules.
No default telemetry of local media files, play histories, paths or downloads. Restrict Kodi JSON-RPC to localhost by default; treat provider credentials as secrets; validate inputs and file parsing; isolate optional app failures. Existing media files should never be deleted as a side effect of a UI or entitlement change.
Acceptance applies to every theme: user can reach Home, Source switching, Guide, Settings, Apps, local library and playback by remote without internet; a title exists in one canonical catalog no matter how many shelves display it; user can replace a default preset with a fully different interface.
Implementation must retain every feature and acceptance criterion detailed in the source specifications below. When a source says “default,” “fixed,” “five destinations,” “Kodi owns” or “Isolde owns,” read it as the behavior of the cited template/adapter unless explicitly foundational, and expose all technically valid alternatives through settings.

Design direction
Isolde is a clean, remote-first television interface inspired by Arctic Zephyr. Its Home screen is a functional launcher, not a streaming storefront: no advertising, compulsory recommendation feed, autoplay preview or enormous promotional billboard. The Library provides deeply curated, poster-focused shelves that remain intuitively browseable without relying on Search.

There is no arbitrary maximum number of shelves per category. Virtualized scrolling and incremental artwork loading should keep navigation responsive as collections expand.

Folder-backed shelf: reflect a chosen local media directory.

Every shelf supports renaming, ordering, show/hide, artwork style, sizing and editing of content rules. Long-press/select context menus expose advanced actions without placing editing buttons across the browsing interface.
5. Visual system
Arctic Zephyr is the stylistic reference: generous negative space, poster-first browsing, understated background fanart and a clear selected-item state. Isolde should resemble a curated personal library, not Amazon Prime.
Use portrait posters as the default for film and television shelves, with roughly seven to nine posters visible per row at a standard television viewing size; offer adjustable density.
Show one clear shelf heading; avoid duplicate explanations or labels under every poster.
When a poster receives focus, reveal title and relevant metadata in an unobtrusive information area.
Provide dimmed or blurred background fanart only as an optional enhancement.
Keep Home focused on functional device and application tiles rather than poster carousels.
Use a consistent muted-rose selection accent against a near-black/charcoal background, with accessible high-contrast options.
6. Remote-first behavior
Directional navigation operates every screen; mouse and keyboard are never required for everyday use.
Home returns to Isolde, including from HDMI display or supported fullscreen applications.
Back follows navigation history and restores the last focused card or shelf.
Left from the first poster in a shelf opens or focuses the category navigator.
Long-press Select opens context actions; focus position remains predictable.
Selected items are identified by outline, size and contrast—not by color alone.
Quick access to All Apps should not require scrolling through favorites or library rows.
7. Separate destination behavior
TV Guide
Present the personal channel schedule as a proper electronic program guide: numbered channels, station labels, current-time marker, proportionally sized program blocks and clock-based playback position. The Home shortcut and permanent navigation tab open the same guide. The guide must function offline with locally retained schedules and media.
Music
A dedicated music experience accommodates albums, artists, playlists, favorites, local playback and user-created shelves without forcing audio into the video Library. Spotify and other applications remain available via the app launcher as appropriate.
Games
Show installed games, Steam titles, recent play and custom collections. Console inputs remain under Home → Sources, while desktop game launchers remain in Games; this avoids duplicating the main HDMI controls.
8. Customization levels
Everyday: Add, remove, rename and reorder categories, tabs and shelves.
Layout: Adjust poster size, shelf density, sidebar behavior, backgrounds and spacing.
Advanced: Define custom widgets, actions, animations, conditional visibility and reusable themes.
Default appearance must be polished without configuration. Customization is powerful but hidden until requested, ensuring that the ordinary browsing experience stays clean.
9. Offline-first requirements
Home, local Kodi browsing and playback, stored artwork, library categories, shelves, personal television schedules, HDMI switching and capture, local music, navigation and settings remain functional without internet access. Online search and streaming are optional additions and must never block the local interface. Configuration and metadata should have local backup/export paths.
10. Validation criteria
All nine source choices (eight HDMI plus Desktop) remain accessible from Home.
Home, Search, Settings, TV Guide and All Apps have unambiguous navigation paths.
Users can reach a known movie through its category and shelf without Search.
A title can appear in multiple categories and shelves without duplicate files.
A category with hundreds of shelves remains smooth with directional navigation.
TV Guide, local library and HDMI remain operational without internet.
No normal task requires pointer hover, a mouse or a keyboard.
The default Home layout fits within a 16:9 television display without scrolling.
Design decision
Commit to five permanent destinations: Home, Library, TV Guide, Music and Games. Home is a one-screen device-and-app launcher. Library is a navigable hierarchy of clearly named categories and effectively unlimited poster shelves. Search supplements this structure; it never replaces it. This keeps Isolde clean at first glance and extraordinarily organized in depth.

OFF is an enforced network boundary for search, not merely a results filter. A Web OFF query must neither contact external search, metadata, or provider APIs nor display previously cached online results. It uses only titles and metadata already available from Kodi. If nothing matches, show “Not found in your Kodi library.” This restriction applies to the search subsystem; it does not globally disable unrelated Kodi services or other Isolde networking.
13.2 Search flow and results
Search opens from any Isolde tab or screen, preserving the user’s current focus and position. A clearly labeled Web toggle is on the search page.
Typing “Stardust” proposes distinct movie identities (e.g., Stardust (2007) and Stardust (1974)), each with title, year, media type and poster when available. Only Kodi matches are eligible while Web is OFF.
With Web ON, merge Kodi and online matches into a single result per distinct title; match reliably using TMDB/IMDb IDs where known, and cautiously fall back to title/year. Never merge remakes or identically named films.
Selecting a result opens one title detail page with synopsis, artwork, metadata and available viewing actions. Kodi remains the source of truth for ownership, playability and watch progress.
13.3 Watch actions and their meanings
Watch Locally: Show only when a playable matching item is present in Kodi. Opens playback directly in Kodi and returns correctly to Isolde.
Watch on [connected service]: Show when Isolde recognizes the app/account integration, current regional title availability is reported, and a supported launch route exists. Do not equate an installed app with an active subscription or entitlement.
Available on [service]: Show a reported subscription, free, rental or purchase offer when online discovery is enabled, even if the service is not connected. Distinguish offers from confirmed entitlements.
Unknown or unavailable: Explain when an online offer cannot be verified; do not fabricate provider availability, account access or deep links.
13.4 Discovery services and safeguards
Kodi JSON-RPC adapter: query local movies, TV shows, Kodi playlists, tags, library nodes and IDs. Use Kodi artwork and watched/resume status where provided.
Online discovery adapter: investigate TMDB title search, details and watch-provider information as a starting point. Provider offers must be checked for region, freshness, attribution and API terms; JustWatch or a licensed availability source may be considered later.
Result-matching engine: correlate external IDs first, then carefully reconcile alternative titles, release dates and media types. Deduplicate per distinct work without losing multiple viewing options.
Provider/launcher adapter: map available offers to installed or configured streaming apps only where a platform-supported deep link/launch method exists; otherwise provide an informational listing.
Settings: remembered Web toggle; preferred country/region; prefer local playback; selected connected services; optional watchlist. Disable external searches immediately when switching Web OFF.
Privacy and resilience: minimal search telemetry, no transmission of local library titles while Web OFF, graceful degradation on API outage, clear stale-availability labeling, and no assumption that provider availability guarantees user access.
13.5 Suggested modules
services/search/{search-controller,kodi-adapter,online-discovery,identity-matcher,availability,provider-launcher,watchlist,cache}. UI components: SearchOverlay, SearchResults, TitleDetails, ViewingOptions and WebSearchToggle. Search/controller must block online adapter requests when Web OFF.
13.6 Implementation sequence and acceptance tests
MVP: local-only Kodi search for titles, shows, playlists and tags; open a result and play a locally owned movie. Validate zero outbound search requests.
Add the visible, persistent Web ON/OFF toggle; enforce OFF at service/request layer, including cached online result visibility.
Add online movie/TV identification with year disambiguation; deduplicate local and online representations by identity.
Add region-aware provider data and separate “Watch Locally,” “Watch on connected service,” and “Available on” states.
Add supported app launch/deep-link integrations, error states, watchlist, and searches by person/genre later.
Test example: With Web OFF, searching Stardust lists only matching Kodi entities and makes zero third-party search calls. With Web ON, independently identifiable Stardust releases may appear, but no provider entitlement is assumed.
13.7 Non-negotiable experience rules
Search must feel native to Isolde, be navigable by remote, preserve the current screen, work without internet while Web OFF, and never force the user through Kodi’s home screen for local playback. Search is a discovery and routing layer, not a duplicate media database.


14. Isolde Linguist — Offline Subtitle System
Offline transcription and translation for your personal media library.
Purpose. Let people enjoy Japanese, Korean, Mandarin, Cantonese, and other foreign-language films and television even when English subtitles cannot be found. Linguist operates locally once its optional language packages have been installed; no account, subscription, video upload, or cloud API is required.
14.1 Experience and product language
Brand the feature “Isolde Linguist.” Use clear functional labels: Find Subtitles, Translate Subtitles, Generate Subtitles, Subtitle Queue, and Edit Subtitles.
Describe the processing transparently as local speech recognition and machine translation. Avoid vague AI branding without falsely claiming that automated models are not involved.
Show language, source, quality status, and whether subtitles were found, translated, or generated. Keep the system optional and never start processing an entire library without permission.

14.4 Proposed interface
On a movie or episode detail page: Subtitles → Available tracks → Find locally → Translate existing track → Generate from audio. Display status, target language, source language (with manual override), and the location where the subtitle will be saved.
For a series: offer subtitle coverage (for example, 6 of 24 episodes), selection of missing episodes, queueing, pausing, cancelling, retrying, and a per-episode review/edit screen. Scheduling may prioritize idle time and automatically pause when a game or demanding task is active.
14.5 Technical design
Discovery: check Kodi subtitle streams, external subtitle files, and configured local paths; identify missing English tracks.
Audio: use FFmpeg to extract a speech-friendly track when transcription is requested.
Speech recognition: evaluate local models such as faster-whisper against Japanese, Korean, Mandarin, and Cantonese sample episodes.
Translation: evaluate installed offline language packs/translation engines such as Argos Translate; verify actual language-pair coverage and quality rather than assuming all variants work well.
Timing: preserve subtitle timecodes when translating .srt/.ass; use word or segment alignment when transcribing speech.
Storage: save Unicode .srt with language suffix (for example, Episode 04.en.srt), preserve provenance and status, and avoid modifying the video file.
Kodi integration: select or load generated subtitle files through supported Kodi mechanisms, with read-only library support via a local cache.
Privacy/network: subtitle generation does not send media, extracted audio, transcripts, or text off-device. Package downloads are a separate setup operation, not part of playback.
14.6 Known limitations
Machine transcription and translation can mishear names, mistake singing or music for speech, omit overlapping dialogue, and mishandle historical titles or idioms. Cantonese and other regional varieties need individual validation. Local processing can be slow on CPU-only machines, especially for long episodes. These outputs should be editable and identifiable as machine-generated; no promise of professional-subtitle quality.
14.7 Roadmap
Linguist 1.0 — Existing files: Detect subtitle coverage; translate existing source-language .srt subtitles offline; preview and save English .srt; select tracks in Kodi.
Linguist 1.1 — Missing-subtitle generation: Add audio extraction, local speech recognition, translation, status/progress, and cancellation.
Linguist 1.2 — Library-scale tools: Batch seasons, pause for active gaming, correct timestamps/text, manage naming glossaries and retain corrections.
Linguist 1.3 — Optional enhancements: Assess OCR for burned-in Chinese/Japanese/Korean subtitles and quality improvements based on real-world testing.

15. Founding principle: The Generator Test
If the world goes dark, Isolde stays on.
Isolde is offline-first. Internet connectivity enhances the experience; it must never be required for the core entertainment system to operate. The acceptance question for each feature is: If the internet disappeared permanently and the house had only generator power, would this still work?
No mandatory cloud dependencies
Core startup, local Kodi browsing and playback, HDMI switching, local app launching, navigation, settings, artwork and metadata caches, watch history, and Isolde Linguist must function without external servers.
Graceful degradation
Weather, internet discovery, streaming availability, web apps, and other online services may become unavailable independently without breaking offline features.
Local ownership and restoration
Store layouts, collection definitions, settings, essential metadata, subtitles, and model packages locally. Support backup/export and installation or disaster recovery using pre-prepared offline media.
Third-party limitations
Isolde cannot make external subscriptions, cloud authentication, DRM-dependent games, or internet streaming work offline. Clearly distinguish those from Isolde-owned local functions.
Acceptance test
Disconnect network connectivity completely, cold boot, browse and play Kodi media, change HDMI sources, navigate apps and tabs, use local search, load saved artwork, run installed subtitle language packages, and restore a backed-up layout.

18. Seamless HDMI launch and return transitions
Design principle: switching to a captured HDMI input should feel like opening the content inside its Isolde launcher tile. No capture application window, Linux desktop, third-party player controls, or intermediate setup screen should appear during ordinary use.
18.1 Default animation: Expand
Select: the user focuses and selects an HDMI tile (for example, Nintendo Switch). Isolde immediately dispatches the configured input-switch action to the RS-232 switch.
Expand: the tile enlarges from its on-screen position into a full-screen video surface. Its rounded corners straighten while the surrounding interface fades.
Reveal: as soon as a valid captured signal is ready, show live video inside the expanding/full-screen surface. A subtle source label (for example, Nintendo Switch · HDMI 1) can appear briefly and fade away.
Return: the Isolde Home command restores the dashboard, ideally shrinking the video surface toward the originating tile and returning focus to it.
18.2 Timing, readiness, and responsiveness
Target a short, configurable animation of approximately 200–350 ms, without delaying signal acquisition to match the animation. Start the hardware switch and capture pipeline in parallel with the visual transition. The full-screen surface must remain stable if HDMI handshake, resolution renegotiation, or capture readiness takes longer. Display the selected source icon or still artwork until video is ready; do not show raw capture errors or a flash of the desktop. Never hold an old input’s picture and misrepresent it as the new input.
18.3 Seamless integration implementation
Use an Isolde-owned video surface backed by the capture pipeline (initial candidate: GStreamer on Linux), rather than exposing the capture backend’s own UI.
Keep capture pipeline, video rendering, audio routing, RS-232 switching, and remote input routing separate behind a Source Session Controller.
Apply an explicit state machine: Idle → Switching → Awaiting Signal → Playing → Returning, with Timeout/Error and Recovery paths.
Map Home/Back behavior carefully so gameplay controls go to the HDMI device where supported while the dedicated Isolde Home action always returns to Isolde.
Test video frames, audio startup, frame pacing, resolution changes, and input lag on actual capture hardware. UI animation cannot fix hardware-induced latency.
Handle protected HDCP content as a hardware/authorization compatibility limitation; do not promise all sources can be captured.
18.4 Customization settings
Transition style: Expand (default), Fade, Slide, or Instant.
Duration: adjustable within sensible bounds; include a reduced-motion/animations-off option.
Source label: show briefly, always show, or hide.
Fallback visual: device icon, configured artwork, or neutral blank surface while waiting for a signal.
Return behavior: restore the originating tile and scroll position; if the tile moved or was removed, return to a stable home location.
18.5 Acceptance tests
Selecting each of the eight configured HDMI launchers starts switching immediately and shows a coherent expand-to-video transition.
Slow signal acquisition does not expose the desktop, old input, capture software, or misleading video.
Pressing Isolde Home restores the previous dashboard position and focus.
Fade, Slide, Instant and reduced-motion settings work without changing source logic.
A disconnected/unavailable source shows a branded error with Retry and Back; Isolde remains fully navigable.
All switching and transition behavior works with internet unplugged (Generator Test).
19. Managed capture backend and automatic installation
Managed Backend Principle: Isolde is responsible for provisioning, configuring, launching, monitoring, and recovering its essential media engines. Kodi is the required local-media backend; GStreamer is the default required capture framework. Users should not need to install or operate separate capture software just to use HDMI inputs.
19.1 Bundled installation and offline recovery
The standard Isolde installer provisions Kodi and the GStreamer runtime with the capture, decoding, audio, and video-output plugins required by the supported Linux distribution.
Ship an offline installation or recovery image containing tested dependencies and compatible packages; no account, download, or live repository is required to restore core functionality (Generator Test).
Record component versions, validate package integrity, and update only from tested compatible versions. Updates are optional, user-controlled, and never required to keep using existing media or inputs.
Install the capture engine even when no capture hardware is attached. Show HDMI capture setup as Not configured rather than failing installation.
19.2 First-run capture setup
Discover supported video and audio devices using Linux facilities such as V4L2 and the local audio subsystem; display detected devices with clear names.
Offer automatic selection of a compatible capture device and an advanced manual override. Probe formats, frame rates, and audio availability without making performance promises before testing.
Test live picture, audio, frame pacing, and responsiveness; save a known-working pipeline configuration locally.
Provide a guided mapping for the eight RS-232 HDMI switch inputs, including label, icon, switch command, and expected capture device. Do not confuse eight upstream HDMI inputs with eight physical capture devices.
Detect missing or disconnected hardware and show Retry, Configure, and Return Home actions without exposing a third-party application window.
19.3 Normal operation: invisible capture engine
Pressing an HDMI launcher starts its RS-232 switching command and opens Isolde’s own capture-backed video surface using the Expand transition from Section 18. GStreamer performs video/audio capture beneath the interface; users see no OBS window, GStreamer controls, shell, or Linux desktop. Isolde manages the session, overlays, volume, source label, and Home-to-return behavior.
19.4 Backend responsibility and limits
Default backend: GStreamer. OBS may be a diagnostic/prototyping tool but is not required for the finished user experience.
Keep the backend behind a replaceable capture adapter; future support for another Linux engine should not require rewriting the home screen or HDMI widgets.
A software install does not imply that every capture card supports Linux or meets the desired latency and resolution. Maintain a tested hardware compatibility list.
HDCP-protected source capture is constrained by hardware and authorization; do not promise that protected streams can always be captured.
Keep Kodi and GStreamer independent: failure or restart of either must not crash Isolde’s shell or disable ordinary local navigation.
19.5 Settings and acceptance tests
Settings → System → Components displays Kodi and GStreamer status, version, health, and repair/reconfigure actions; default UI hides implementation complexity.
Settings → Inputs → Capture provides automatic/manual device selection, signal test, audio routing, and eight-input mapping.
Fresh offline installation on a supported Linux machine provides a functioning Isolde interface, Kodi integration, and installed capture engine with network disconnected.
With no capture device present, Isolde installs successfully; plugging in a supported capture device later enables configuration without reinstalling.
Selecting any configured HDMI tile reveals live feed through Isolde’s integrated transition; Home reliably returns to the originating dashboard position.
A missing signal, backend crash, or incompatible format produces an Isolde error and recovery path without exposing underlying application windows.


3. Media access, Borrowed, subscriptions and achievements
Source file: Isolde_Plan-borrowed.docx
Isolde — My Library, Borrowed & Unified TV Guide
Status: Product and implementation plan
Scope: Isolde's unified media catalog, cross-provider live television guide, source-aware recordings, recommendations, subscriptions, and achievements.
Guiding idea: My Library is what stays when the internet goes out. Borrowed is everything you can enjoy while the doors are open.
1. Product vision
Isolde assigns media to two underlying access classifications, not two mandatory pages, tabs, or separate catalogs:
My Library: User-controlled media and files accessible independently of a third-party streaming entitlement. Kodi-managed local movies, television, music, games, and home videos belong here; so do compatible files on removable drives or user-controlled LAN shares, with offline availability accurately indicated.
Borrowed: Content accessible through outside services: active streaming subscriptions, free ad-supported services, authorized provider cloud DVR recordings, temporary catch-up programs, and titles saved for later through those services. Access depends on the provider, the user's entitlement, territory, and availability window.
A title can have both a local copy and one or more Borrowed sources. It should appear as one logical title with multiple ways to play, rather than unnecessary duplicates. Borrowed does not mean downloaded, locally retained, or legally owned.
Isolde does not interrogate where users obtained files placed in their watched folders. It does not market new streaming subscriptions or DRM-restricted purchases. It can use and display services a user has already connected, and answer explicit searches with informational availability across other services.
2. Main navigation and presentation
Users may create any page layout with Isolde's interface builder. Neither My Library nor Borrowed is a required page. The following are optional sample destinations and widgets, not a prescribed navigation structure:
My Library — locally controlled movies, series, home videos, music, and games; custom categories and shelves.
Borrowed — saved, recorded-in-provider, and recommended titles accessible via connected services.
Live TV Guide — a consolidated electronic program guide (EPG) across supported services and personal PseudoTV channels.
Recordings — scheduled, in progress, completed, failed, and provider-managed cloud recordings. Each carries a precise storage/access label.
Search — unified search with local-first behavior and source availability details.
Subscription Manager — renewal dates, user-entered prices, detected Isolde usage, cancellation help, and review decisions.
Achievements — user-controlled, optional entertainment trophies and collection milestones.
A shelf filtered to Borrowed can show widgets like Continue Watching, Cloud DVR, Saved for Later, From Your Active Subscriptions, Leaving Soon (when verified), and Airing This Week. None of these rows should require users to sign up for another service.
2.1 Page-builder integration: access classes, not pages (required)
Authoritative UX requirement: The unified title catalog, playback-source records, and access entitlements are independent of user-created pages and shelves. The terms My Library and Borrowed describe how a title is accessible, never where the title must be displayed. Users can mix both types in the same shelf or separate them into any arrangement.
Every media shelf, carousel, poster grid, recommendation row, and dynamic collection widget must offer composable rules:
Sources / access: all currently playable media, local only, Borrowed only, chosen providers, chosen folders, local recordings, provider DVR, or a combination.
Content: movie / episode / show / music / other supported media; genre, tags, franchise, country, release period, studio, collection, user rating, watched state, and other available metadata.
Availability: currently playable, offline-ready, included in an active subscription, provider-recorded, and other supported states.
Organization: alphabetical, recently added, recently watched, random, user order, custom ranking, and recommendations; limits and exclusions.
Placement: shelves can be reused on arbitrary user-defined pages, including a one-page all-in-one interface, separate Movies/TV/Music pages, or genre-specific pages. Navigation widgets link to pages without enforcing content classes.

2.2 Graceful availability changes and offline behavior
Internet disconnected: Titles accessible only through online Borrowed sources quietly disappear from dynamic shelves filtered to currently playable media. Local files and truly offline-ready material stay present. Do not show blank poster slots, dramatic alerts, or an unsolicited offline warning.

Required storage model: keep title, access_source, entitlement, shelf_definition, and saved_collection_membership as separate logical entities. Dynamic shelf results are calculated from source/availability and metadata; saved lists persist independently of access. Do not duplicate the underlying title merely because it belongs to multiple shelves.

7.1 Passive recommendations

Free services the user deliberately enables, when current availability can be verified.

Other streaming services.

8.1 Core reminder

Source-dependent tracking: do not falsely award a "watched" achievement from a mere app launch.
Gamification principle: Celebrate what users enjoyed or deliberately managed, not money spent, subscription accumulation, watch-time maximization, or daily-login streaks.

14. Acceptance criteria
A Kodi-local movie works while disconnected from the internet even if its streaming-source record has expired.
One title available locally and through multiple providers appears as one logical title with multiple clearly labeled sources.
Borrowed never calls a cloud DVR item a local file.
A channel with no supported recording interface does not show a misleading Record button.
A connected provider with guide access but without recording support still contributes guide information if integration allows it.
A canceled/expired subscription is removed from proactive playable recommendations without deleting the user's watchlist or history.
Explicit search can show other services informationally; passive recommendations don't push new spending.
"Unused this billing period" notifications describe only observable usage through Isolde and are fully configurable.
Achievement unlocks are backed by actual history or evidence, not assumed from app launches.
Offline operation preserves all core local library, PseudoTV, achievements, and UI behavior.
Every integration accurately states its capabilities and constraints.
Users can entirely hide Borrowed, guide, recording, and gamification sections without degrading local media playback.
A user can put local, subscription, and cloud-DVR titles on one Movies page in a unified shelf; alternatively they can create separate access-specific or genre-specific pages with the same widget system.
Disconnecting the internet removes online-only titles from available media shelves without gaps, warnings, deleting title records, or altering local items; reconnecting restores eligible titles automatically.
Canceling a subscription removes only titles whose last playable source was that entitlement; films also available locally remain visible and playable.
User-curated collections, watchlists, and history retain unavailable title references and can separately show or hide inaccessible media based on the collection's filters.
The page builder never forces My Library or Borrowed navigation items, and every dynamic media widget can filter by source, genre, availability, and chosen providers.

Product north star
My Library is what stays when the internet goes out. Borrowed is everything you're enjoying while the doors are open.
Isolde should make both enjoyable and convenient while always being honest about which media the user controls, which access is temporary, and which actions a connected service actually supports.

Live TV Engine & Persistent Channel Guide
Implementation specification  |  Isolde 0.0.1.1 planning  |  October 2026
Purpose: Replace PseudoTV-style lengthy startup indexing and unstable schedules with a fast, offline-first, user-owned cable-TV experience. The electronic program guide (EPG) is both a viewer and the central management interface for building channels.

Instant-read design: a cached guide is visible without a scan or global schedule regeneration.
User ownership: exportable channel definitions, custom artwork, lineup order, playlists, and schedules.
Separation of concerns: Kodi may index/play media, but Isolde owns channel rules, schedules, and EPG state.

The guide displays station numbers, station logo and name, current/next programs, progress bars, and a horizontal timeline. A visible “+ Add Channel” row or button is available in the guide, and can be reached with a remote. Opening a program offers Watch, Details and context-sensitive options. Smart playlist content changes trigger targeted refresh, not a destructive schedule rebuild.

Store all scheduled start/end instants and timezone identifiers in an embedded database. 6.1  Suggested data model
Use SQLite in WAL mode as the default on-device store. Suggested core tables: media_items, media_sources, channels, channel_rules, channel_assets, channel_schedule_modes, schedule_slots, schedule_generation_state, guide_sources, guide_channels, service_auth_refs, channel_order, playback_positions, index_jobs and schema_migrations.
Each schedule slot should include immutable ID, channel ID, media/provider item ID, UTC start/end timestamps, generation version, status, optional content metadata snapshot, optional bumper slots and source/origin. Unique constraints must prevent overlapping committed slots on a channel. Local secret tokens should be stored via OS secret storage, not in cleartext exports.
6.2  Scheduling algorithm
1. At creation, evaluate rules against cached catalog and produce a stable candidate set.
2. Derive a per-channel seeded ordering and store its scheduling cursor.
3. Write slots transactionally until the configurable rolling horizon (default proposal: 7 days) is filled.
4. On subsequent starts, read existing slots directly; append only beyond the horizon or repair changed portions.
5. On a channel tune, locate the slot whose [start, end) contains now; seek to now - start.
6. On library update, record invalidation of affected candidate sets and future uncommitted slots rather than reindexing the full catalog.
7. Use optimistic versioning/transactions to avoid two simultaneous scheduler workers changing the same channel.

async function kodiRequest(method, params = {}) {
  const response = await fetch("http://127.0.0.1:8080/jsonrpc", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", id: 1, method, params })
  });
 
  if (!response.ok) {
    throw new Error(`Kodi HTTP error: ${response.status}`);
  }
 
  const data = await response.json();
  if (data.error) throw new Error(data.error.message);
  return data.result;
}
 
const library = await kodiRequest("VideoLibrary.GetMovies", {

3. Organize by both console and intellectual property
These dimensions solve different questions: “What can I play on PSP?” and “What games do I own in the Kingdom Hearts universe?” Neither should be the only hierarchy.
Platform: original release platform / owned edition (PSP, GameCube, PS2, etc.).
Franchise (IP): Kingdom Hearts; subseries optionally groups closely related titles.
Genre & tags: RPG, rhythm, co-op, kids, short-session, favorites; user-defined tags.
Collections: manual lists spanning platforms (e.g., “Play with Friends,” “Childhood Favorites”).
Smart collections: saved rules combining fields (e.g., PSP + RPG + not completed).
Treat “franchise,” “series,” and user tags as separate metadata. A game may belong to multiple collections but has one canonical catalog record per owned edition. Where multiple platform editions exist, group them on a single game-detail page with a “Choose Version” option—or allow separate cards as a preference.
4. Game detail and launch experience
Each cover opens a details view with large art, synopsis, franchise, platform(s), tags, play history, and a prominent Play button. If only one configured version exists, Play launches immediately; if multiple versions are installed, offer a default edition and a version selector.
Isolde resolves game → edition → local file/installed PC title → launcher profile → emulator or native executable.
On exit, return to the exact shelf and scroll position in Isolde.
Display controller compatibility and configurable input profile before first launch; don’t force setup on every play.
Distinguish resume (launch the game) from emulator save-state load; unsupported save states should not be assumed.

6. Import and metadata pipeline
Add library folders per platform or PC launcher. Scan in the background on demand or at startup, with throttling.
Detect files and propose game matches using platform + filename; never silently overwrite manual corrections.
Resolve duplicates and variations (region, disc, revision); show a review queue for uncertain matches.
Download metadata/cover art only when explicitly enabled; cache everything locally for offline use.
Always allow manual game creation, cover upload, franchise assignment, tagging and editing.
If artwork is missing, render a clean title tile rather than breaking a shelf.

Virtual keyboard search works offline across titles, alternate titles, franchises and tags.
Progressive loading, thumbnail caching and virtualization for libraries with thousands of entries.

10. Decisions to defer until PC hardware is known
Which high-end emulators are practical; any Linux-specific capture or controller edge cases; playtime reporting where emulators do not expose it; and whether PC game storefronts should be indexed through plugins or manually linked. None of these should block the library UI or data model.
Recommended default: launch the Games page with Continue Playing, Favorites, Recently Added, PSP Games (when populated), and All Games. Make Franchise and Tag shelves one-click additions. This avoids a wall of empty categories now without limiting growth later.


7. Video services and downloaded files
Source file: Isolde_Video_Services_Downloads_Plan(1).docx
Isolde | Video Services & Download Support
Implementation specification  •  Optional Linux apps  •  Offline-first local media
DECISION: Support FreeTube as an optional YouTube-oriented Linux application, Parabolic as an optional advanced download manager, and native download-folder ingestion in Isolde. No custom YouTube client or fully integrated video-service interface is required for the initial release.
1. Product goals
Let the user choose whether and what to download; Isolde should not remove or discourage supported download controls.
Use mature Linux applications instead of recreating a web-video service client.
Store downloaded media as ordinary, user-accessible files in user-selected folders.
Automatically bring completed downloads into Isolde’s indexed local library, custom pages and optional Live TV channels.
Preserve Isolde’s offline-first design: previously saved compatible files remain playable without network, account login or the downloading application.
Keep video service integrations optional; core media playback and library functions never depend on them.
2. Supported application roles

Integrations should be version-aware: application download behavior, paths, formats and Flatpak permissions can vary. Do not hardcode undocumented integrations or promise one-click handoff before it is tested.
3. User experience
3.1 Installing / launching
In Settings → Apps → Supported Apps, display FreeTube and Parabolic as optional supported Linux programs.
Where packaging is supported, provide an explicit install action, version/status indicator, and launch shortcut. Never silently install optional applications.
Let users place either application anywhere in the page builder (app tiles, shortcut widgets, favorite apps, menu pages).
Provide a simple Return to Isolde remote shortcut, consistent with other external apps.
3.2 Download folders
In Settings → Media → Watched Folders, let the user add arbitrary folders (including FreeTube or Parabolic download directories).
Offer readable suggestions for common locations but let the user browse and choose; do not assume ~/Videos/FreeTube exists.
For each folder: enable/disable watch, media category, recursive scan option, destination library/shelf, and optional automatic Live TV eligibility.
Allow multiple paths, including external disks, with clear offline/unmounted status and no deletion of metadata merely because a drive is temporarily missing.
3.3 Completed downloads
Use filesystem notifications where available, plus a low-frequency reconciliation scan for missed events.
Never index partial or still-growing files. Check temporary extensions, stable file size and successful media probing before publishing an item.
Use ffprobe or equivalent to confirm file readability and extract duration, video/audio streams, language and subtitles.
Deduplicate using stable file identity and optional hashes; avoid duplicate items if a file is moved or renamed.
Expose newly added files in My Library, Recent Additions, arbitrary dynamic shelves and eligible personal television channels.
4. Minimal integration architecture
FreeTube / Parabolic → user-selected destination folders → Isolde filesystem watcher → completed-file validation → local media index → library shelves / page-builder widgets / Live TV Engine → playback.

4.2 Privacy and security
No Isolde account or service sign-in required just to manage local downloads.
Never transmit local watch histories, file paths, or downloaded media lists as telemetry by default.
For Flatpak installations, request access only to explicitly selected folders; display permission failures with actionable recovery steps.
Do not run download utilities with elevated privileges or execute arbitrary commands derived from downloaded filenames.
Handle untrusted metadata and filenames defensively; sandbox thumbnail/media parsing where feasible.
Respect applicable copyright and service requirements while keeping local-library organization neutral toward file provenance.
5. Download behavior and optional handoff
Phase 1 should rely on each app’s built-in download interface. A user opens FreeTube, selects its own Download action, chooses a destination, and Isolde imports the finished file. Parabolic remains an optional separate app for advanced workflows.
Future enhancement (not launch-blocking): a context action such as “Download with Parabolic” can be added only when a reliable supported URL handoff is verified. Avoid fragile screen scraping or assumptions about undocumented command-line interfaces.
6. Offline-first behavior
Previously downloaded videos remain in the same user-accessible directory even if the app is uninstalled.
No internet or service API call is required to display or play indexed local media.
Loss of internet hides or marks unavailable online views, not local downloads.
Library index can rebuild from local files and backup files without FreeTube, Parabolic, Google sign-in or a third-party metadata endpoint.
If the source file is removed by the user, surface the missing-file state without silently deleting watch history.
7. Acceptance criteria
Given a completed FreeTube video in a selected watched folder, Isolde discovers it and makes it playable in a local shelf without manual library rebuild.
Given a partially downloading video, Isolde does not show a playable library item until the file is complete and valid.
Given an external drive temporarily disconnected, Isolde preserves media metadata and restores availability when reconnected.
Given no internet access, Isolde can launch, browse and play previously saved compatible files.
Given two monitored applications depositing the same media file, Isolde does not create duplicate records for the same local asset.
Given a channel driven by a watched folder, newly ingested content is eligible for future slots without resetting the channel’s established broadcast schedule.
Given a user disabling watched-folder monitoring, Isolde stops indexing new files there without deleting them.
