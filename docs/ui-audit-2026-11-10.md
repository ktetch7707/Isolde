# UI audit and repairs — November 10, 2026

User scope: improve app icons, overflowing menus and complicated interactions without removing features. This is a UI repair campaign; existing software acceptance is not raised by source changes alone.

## Findings and selected changes

| Finding | User impact | Repair / evidence |
| --- | --- | --- |
| UI01: packaged artwork exists only for YouTube; native artwork depends on the guest's desktop theme | Letter tiles and generic installer/package icons make apps difficult to recognize; offline defaults vary by installation | Package bounded vector brand artwork with pinned provenance and semantic internal-app icons; preserve managed/profile-scoped artwork and user overrides |
| UI02: wrapper Icon metadata can mask the application's own icon | Steam can look like a cardboard installation package | Prefer packaged artwork; skip generic wrapper artwork when vendor metadata is available; regression with a generic wrapper |
| UI03: built-in app types are excluded from app artwork resolution | Movies, Shows, Settings and Store remain letter placeholders | Permit packaged artwork for registered internal apps without enabling arbitrary icon reads |
| UI04: Studio dialog height and list height use different available-space calculations; help can consume the viewport | Long menus and large type can push choices outside the visible dialog | One bounded height budget; pinned heading, concise help and scrollable fully wrapped choices with visible selection |
| UI05: inspector rows have a fixed height and elide long property/action names | Different actions can become indistinguishable | Wrap labels and size rows from actual text while retaining typed toggles, colors, all advanced controls and exact remote selection |
| UI06: System rows reserve a fixed status width and fixed row height; title width is unbounded | Narrow screens and large type collide, while technical placeholder copy competes with actual settings | Responsive title/status allocation, content-based row height and concise outcome-oriented guidance |
| UI07: internal mode names and implementation wording leak into menus | Users must interpret uppercase mode IDs, atomicity and draft internals | Human-readable operation names and plain-language save/remove instructions; preserve every action and confirmation |
