# Page Studio: approved usability expansion

User decision, 2026-10-21: accept ideas 1–10, 15–16 and 18–20 from the proposed feature list. Ideas 11–14 and 17 are not requested by this expansion. Existing independent safety/accessibility requirements remain in force; this decision adds no contrast assistant, focus-route editor, remote test mode, destination previews or artwork-library feature.

These are mandatory acceptance requirements of the existing **open** gates below, not new top-level tasks or implementation credit. Original idea numbers are retained for traceability. Implement in backlog order, completing reopened T19/T20 work first. Reuse existing session, schema, appearance, action and profile authorities; no parallel layout store or executable templates. If a bounded operation cannot succeed, explain the actual failure and preserve the draft.

| Idea | Feature and organization | Owning open gate | Acceptance requirement |
|---|---|---|---|
| 1 | Component presets | T21.8, T21.11 | Add offers visual starting variants such as round icon, poster, wide tile and text where supported. Choosing a variant creates an ordinary editable component through shared appearance data; no fixed renderer branches or extra setup required. |
| 2 | My components | T22.2 | Save a named component or section and insert an independent copy on another page. Make independent copies versus linked instances explicit. Preserve supported content, styling and managed assets; allocate fresh identities and remap internal links safely. Bound saved items and retain profile isolation. |
| 3 | Copy appearance | T22.2 | Copy and paste compatible presentation properties without changing content, actions, source membership or placement. Show incompatible properties without silently coercing them; one accepted paste is one undo transaction. |
| 4 | Linked styles | T22.2 | Create named shared styles, choose them on compatible components, override individual properties and reset overrides. Preview affected instances before a shared change; undo restores the whole change. Reuse existing tokens/symbol inheritance rather than another styling system. |
| 5 | Templates with content slots | T22.1 | Templates expose named roles such as Main shortcuts, Featured content and Apps. Fill roles with supported actions, apps or Kodi sources without rebuilding geometry. Empty and unavailable slots remain editable; templates neither curate Kodi collections nor imply provider availability. |
| 6 | Replace in place | T21.8, T21.11 | Offer compatible replacement types while preserving valid placement, appearance, labels and links. Preview retained/lost properties before acceptance; validate the entire replacement, preserve incoming references where semantically valid, and support cancel/undo without data loss. |
| 7 | Edit this section | T22.2 | From a container context, isolate its contents in a temporary editing workspace and return to the exact page selection/scroll position. Isolation must not resize the authored section or change exported geometry; use the existing nested scope model and make the current scope visible. |
| 8 | Responsive layout rules | T22.1 | Expose supported Wrap, Scroll, Shrink and Stack policies by section type, with minimum sizes and aspect constraints. Preview alternate viewport shapes without mutating saved placement. Persist validated bounded rules; refuse unsupported or overflowing combinations. Remote/pointer edits yield identical data. |
| 9 | Content stress testing | T23.1 | Editor-only scenarios exercise long titles, missing art and empty/large collections using production renderers and bounded synthetic inputs. Switching or exiting scenarios restores real data and exact edit position; sample data never enters Apply/export or changes Kodi/provider state. |
| 10 | Design reference overlay | T22.1, T23.4 | Import a bounded reference image, adjust opacity, temporarily hide it and build over it. Keep it private to the editor, excluded from runtime layouts and portable exports. Cancel and profile teardown remove temporary state safely. This extends the existing reference-overlay requirement, not screenshot-to-layout automation. |
| 15 | Searchable action picker | T21.8, T21.11 | Search supported actions by familiar intent and aliases, such as open HDMI or search movies, with remote-accessible category browsing as an alternative. Reuse the validated action registry, localized labels and capability states; no arbitrary commands, fabricated actions or automatic execution on selection. |
| 16 | Useful empty states | T21.6–T21.8 | Empty collections and images expose the relevant Choose apps, Choose source or Choose image action on selection. Distinguish not configured, genuinely empty, loading and unavailable states. Keep helper affordances editor-only and restore focus after choosing or canceling. |
| 18 | Named page versions | T23.3 | Save bounded named milestones, visually compare against the current draft and restore a selected page/version as a reversible draft transaction. Preserve the current draft until explicit acceptance; Apply remains atomic. Handle missing sources/assets honestly and keep versions profile-scoped with explicit retention limits. |
| 19 | Household editing permissions | T23.4 | Provide profile-level editing permission and a simple editor lock against accidental edits. Enforce restrictions at command/apply/import entry points as well as UI entry. Offer configurable restrictions for supported purchase/install actions and destinations through existing authorities; unsupported integrations must be identified honestly. Do not imply a security sandbox over external apps. Maintain an authorized recovery path and test teardown/profile switches. |
| 20 | Page health check | T23.2 | Before Apply, present actionable validation findings for unreachable controls, broken internal destinations, clipped labels and required empty content. Selecting a finding focuses its page/component/property. Separate blocking data errors from dismissible design findings; allow intentional empty components. Diagnostics use bounded actual layout/action state and never claim external-provider availability without evidence. |

## Verification and completion

For each owning gate, extend component/session and QML navigation suites as applicable: remote journey, pointer parity, preview/cancel, undo/redo, profile teardown, invalid input and atomic write failure. Run the task's Verify commands and both standing visual fixtures when shared visuals change. T24.1–T24.3 must include these workflows in installed acceptance and uncoached discovery, including empty/error states and bounded large documents.

The table is an acceptance checklist attached to existing unchecked gates, not separately weighted progress boxes. No existing completed foundation is reopened merely to provide supporting APIs. If implementation reveals a genuine prerequisite regression, record it explicitly before changing task credit. Current active task count and completion percentages remain unchanged by this planning addition.
