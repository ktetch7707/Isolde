# Component semantics — user clarification, 2026-10-20

This is the current requirement for T21/T22/T24. It supersedes the earlier six-family catalog wherever semantics differ. Matching a screenshot with separately placed cards does not implement a carousel. The pastel preset currently does that for apps and recent content; historical visual passes establish appearance only.

## Catalog and editing

Expose App carousel, Button carousel, Recently viewed carousel, Shape, Button, Image and Text directly in Add component. Keep Media shelf and other genuinely implemented widgets available as additional choices. “App bar” may remain an internal compatibility identifier; the editor calls it App carousel. A generic Kodi shelf or a group of fixtures cannot masquerade as Recently viewed.

A carousel is one selectable/resizable page component with an owned collection. Its inspector has Content, Layout, Appearance and Actions where relevant. Edit items opens a focused collection editor; users never position each generated app/media card on the page. Button carousel children remain individually editable through Edit contents. Moving, duplicating, deleting, undoing or exporting the carousel preserves the collection and its settings as one unit. Child identities are stable. Changing the visible capacity does not delete or recreate collection members.

All components have an optional visible label, with show/hide, placement, typography and inherited color controls. A carousel's label is its heading; child labels are independently configurable. Distinguish visible label from editor name, accessibility name and content text. Hiding a label must not erase text or make an interactive item nameless. Blank accessible names derive from a real app/page/action title where possible; otherwise require a name before enabling interaction. Text components provide independent body text, not a workaround for missing labels on other components.

Shared presentation includes size, spacing, card aspect, art source/crop, labels, opacity, corners, surface and focus states. Different rows may have different styles. One selected component and one context window remain visible over the actual page. All collection editing, ordering and overflow navigation must work with D-pad, Confirm, Back and Menu; pointer editing writes identical data.

## App carousel

- Content mode: **All installed apps** or **Selected apps**. All follows the active profile's eligible application registry; newly installed apps appear automatically. Selected stores validated app IDs and a user-defined order; offers a remote multi-select picker with Select all/Clear and clear missing-app states. Application discovery is not package installation.
- Layout: visible capacity, card size/aspect, spacing, icon/label appearance and scrolling behavior. Content membership is independent of capacity; remove the current accidental 16-item authoring limit in favor of explicit validated collection bounds within the shared document/component limits.
- If the eligible collection exceeds visible capacity, the last visible slot is **More apps**, with remaining apps reachable there. Otherwise omit it and show the actual collection. For capacity one with overflow, More apps is the sole slot. More opens the full eligible collection, including already-visible members, using the same All/Selected filter and order. It never silently expands a selected subset to all installed apps and never opens Search.
- The full collection is a remote-friendly contextual gallery with pagination/virtualization. It can be reused by T26, but T21 must not wait for T26 or redirect to an unfinished global destination. Back restores the exact More apps origin; app launch/return restores the exact app. Reordering or uninstalling an app cannot strand focus.
- Empty All explains that no eligible apps are available; empty Selected offers Choose apps in the editor. Missing selected apps are flagged and repairable; no fake launch succeeds. Dynamic entries do not become persistent hand-positioned button nodes.

## Button carousel

Same collection/capacity/overflow and remote navigation model as App carousel, with **More buttons** opening that carousel's collection. Members are authored buttons with optional labels/art and validated page, action or application links. Support add, remove, duplicate and explicit reorder; no silently discarded overflow or mandatory mouse dragging.

Primary starter pattern: HDMI/input buttons, with user-selected names, order, links and style. Bind only configured supported input actions. Unavailable inputs explain the setup requirement; a visual HDMI button is not proof of working capture hardware. The carousel can contain arbitrary supported buttons, not just HDMI. Horizontal overflow and an optional multiple-row layout are explicit choices; visual grid placement remains a separate page-level concern.

## Recently viewed carousel

- Content is real **viewing/opening history**, ordered most recently viewed first; it is not recently added media or a static list of illustrated cards. Configure total retained/displayed result count (validated 1–50 for the first implementation), visible card capacity, card style, labels, source badges and empty/offline behavior. Result count and visible capacity are separate controls. Overflow scrolls within this bounded collection; optional See all opens its same filtered history.
- Source mode: **Local media only** by default, or **Local and selected supported app providers**. Local history is read from Kodi through the existing bounded bridge. Kodi continues to own media metadata, watched state, resume position and playback. Do not create another media database or invent watched state from recently added titles.
- App integration requires an explicit provider capability to read permitted recent items and safely reopen the corresponding media/app destination. Merely being a web-enabled installed app does not make its history readable. The picker distinguishes supported, unconfigured and unsupported providers with reasons; never read browser cookies/history or scrape a service as a substitute. Enabling a provider requires the relevant account/permission flow. Do not claim working streaming integration from placeholder art. A generic interface and disabled toggle alone do not complete app integration: name an actually permitted adapter and record its working evidence, or keep that part of T21.7 open and report the provider blocker.
- Merge only comparable provider timestamps; retain provider identity and deterministic ordering. Deduplicate within a provider using stable media identity; merge across providers only with an authoritative shared identity, not title matching. Handle missing dates, deleted media, revoked credentials, offline sources and unavailable destinations honestly. Each bridge/provider request is bounded at 50; results and refreshes remain bounded across the merged collection.
- No external requests when providers are disabled, the product is in offline mode, or the relevant online consent is off. One unavailable provider does not block local results. During editing, freeze a bounded snapshot during gestures; refresh cannot move selection. Sample content is explicitly marked editor-only and never saved as actual history.
- Multiple instances can use different counts, source selections and styles. All provider clients and any permitted reference caches are profile-scoped and invalidated on profile teardown. Back from playback restores the exact originating card or a predictable neighboring/recovery target if it disappeared.

## Shape

An independently selectable visual primitive: rectangle, rounded rectangle, ellipse/circle, pill or divider. Controls include fill/gradient, border, opacity, corners where meaningful, dimensions and layer order, using shared presentation data. No executable drawing code.

Choose **Decoration/background** or **Container**. Decoration sits behind content, does not enter runtime focus order and does not intercept its input; it remains selectable via editor Layers. A container owns real children with validated layout/padding/gap/overflow/clipping choices. Children remain separately selectable/editable; moving/deleting the container clearly describes the subtree effect and is undoable. Respect existing nesting/component limits and explicit collision policies. Background use must not secretly change parenting, and changing to a container must preserve visible positions through an explicit validated operation.

## Button, Image and Text

- **Button:** On select → None, Open page, Supported action, or Application. Application uses the same validated launch capability as the app registry, not a raw command. Pick by readable name, show destination, Change/Clear and broken-link repair. None remains an honest unassigned draft state. Links remain independent of appearance and focus restoration follows the invoking item.
- **Image:** managed still image or GIF, with crop/fit/focal point, size, opacity and optional label. Same optional links and accessible interactive/decorative distinction as Button. GIF support must be verified through the real artwork pipeline, including decoded frame/dimension/byte/time bounds and bounded caching; an extension accepted by a file dialog is not support. Default to a still frame; motion is user-controlled, pauses offscreen/in background, and respects reduced motion. No scripts, remote executable content or unbounded decode work. Preserve atomic asset staging, cancel cleanup and export portability.
- **Text:** independent body text with optional separate label; font/size/weight/alignment/wrapping/line limits/color/spacing and a meaningful empty state. Remote text entry must preserve the edited item visibly and restore exact focus. Plain text is the default; no executable markup or code in a layout.

## Presets and acceptance

Rebuild the **packaged opt-in Pastel sky skin** (`config/skins/pastel.json`) and the pastel visual fixture from the same generic components: one app carousel for Favorite Apps, one real Recently viewed carousel, and editable buttons/button carousels for launchers/inputs, with shape/container surfaces where needed. Do not rewrite existing saved user layouts on load. Offer explicit conversion or reapply the updated packaged preset; keep backup/rollback.

The visual fixture may inject deterministic app/history provider responses, clearly identified as test data. It must exercise the production carousel renderer and collection behavior, rather than substitute hand-placed cards or a screenshot. Installed runtime defaults use real providers and honest empty/unavailable states. Existing legacy visual fixtures remain regression evidence, not semantic acceptance of the new preset.

Acceptance must inspect persisted component/collection structure as well as screenshots. Verify All versus Selected, install/uninstall changes, More membership/order, capacity one and boundary overflow, remote reorder/focus return, real Kodi viewed versus newly-added results, unsupported/disabled/offline app providers, independent instances/profiles, GIF/reduced-motion limits, decorative focus exclusion, nested shape editing, labels/links, atomic failure/rollback and both reference recreation/reset pairs. An uncoached user must be able to edit these rows as collections directly from normal Customize Home. T24 still owns broad usability/hardware/offline product gates; these contracts are not implementation evidence.
