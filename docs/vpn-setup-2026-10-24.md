User-authorized T12/network slice, independent of the open Studio gates. The target is an Isolde-operated setup for Surfshark and Proton VPN, default client downloads, a location choice for every eligible application, and CBC Gem automatically opened after a real Canadian egress check. ## Implementation

- Settings → VPN offers explicit default-provider installation, individual install/repair, native provider settings, and account configuration pages opened only by the guest. The system provisioner's default-app phase also provisions both VPN clients. Startup/status perform no downloads or public-IP requests.
- The default setup opens the installed provider app for sign-in and a country connection. “Save connected location” then requests consent to copy that connection locally into the active Isolde profile. Isolde observes the country itself. Browser pages and downloaded WireGuard configurations are optional Advanced tools. The Isolde UI never requests a password, private key, server address or terminal command. Country names use the OS ISO country catalog with Canada and the US first.
- Advanced imported configurations are bounded to 16 KiB and one peer, with known fields, valid addresses/keys/endpoints, full IPv4 routing, and no hooks/scripts. Import reads a private snapshot; libnm imports it into memory, sets profile ownership, user permission, autoconnect off, DNS policy and full-device routes before one AddConnection commit. Private keys are not passed in process arguments or returned in diagnostic JSON. Original downloads remain untouched.
- Saved locations carry the active Isolde profile identity in NetworkManager metadata. Only that profile's locations appear in selectors. Per-app assignments live beside its home layout in `app-vpn.json`, with validated bounds, atomic writes and backup. Invalid rules are not rewritten on load and fail closed for eligible apps; Settings and Store remain reachable.
- The ordinary SessionManager preparation path gates native/web/mock app launches on the assigned location, then performs existing native-return preparation. Failures do not mark an application package broken. Back cancels the helper; failed/cancelled switches restore only the exact previously owned connection. Another profile's or an external VPN is refused, not disconnected.
- Before allowing an assigned launch, the helper confirms the sole active VPN, IPv4 and IPv6 routing through its interface, and a bounded HTTPS country response from IPinfo bound to that interface. The UI discloses this check. No raw public IP is stored. Import adds an IPv6 route into the tunnel even for IPv4-only providers so unsupported IPv6 cannot escape through the physical default route.
- NetworkManager connections are device-wide, even though location metadata and rules are profile-owned. “Keep current connection” explicitly makes no automatic switch. No split-tunnel, ongoing kill-switch, entitlement or streaming-playback claim is made by the source implementation.
