# Portable game installer and optical workflow boundary

The Games page supports two deliberately narrow independent local-install formats: an inert ZIP bundle or an uncompressed POSIX USTAR archive containing `isolde-game.json` with `schemaVersion`, `title`, `platform` and a relative `entrypoint`. Compressed tar variants are intentionally unsupported. The entry point must be a Linux ELF file. Preflight inspects metadata and the ELF header without executing archive contents. Install requires a separate confirmation showing the selected installed file runtime and new profile-private destination.

The helper enforces a 512 MiB archive limit, 10,000-member limit and 2 GiB total expanded-size limit; rejects encrypted entries, duplicate/non-canonical paths, symlinks, unsupported special files and unsafe entry points; writes only into a new staging directory; and atomically publishes the completed package. Existing installations and saves are not overwritten or removed. Cancellation terminates the bounded helper and removes an uncommitted staging directory where possible. Failed catalog registration preserves the installed private folder for recovery rather than silently deleting it.

Play resolves the registered relative entry point through the selected installed native file runtime. The package tree is mounted read-only in the game session; profile storage remains isolated. The title still runs as user-supplied executable code after the explicit install and Play actions, so the user must trust its source.

An explicit Uninstall action is offered only for a managed ZIP installation that has no other catalog/edition references. The helper verifies the private install marker, exact directory/file inventory, file sizes and SHA-256 digests before removing that install folder. Modified or unowned files cause a refusal; only the Isolde-managed install subtree is eligible, never its sibling profile/runtime/save folders. Ordinary Remove from library remains catalog-only and preserves all files.

The optical page observes mounted read-only ISO9660/UDF volumes and unmounted drives reporting media, without autorun. Unmounted data media can be explicitly mounted through UDisks with a read-only request; the returned mount is checked against the selected device and read-only state before use. ISO9660 primary volume descriptors provide a durable descriptor fingerprint and volume-set/disc sequence; changing mountpoint or drive does not change it. This is not a full-disc content hash or hardware serial and cannot distinguish bit-identical copies or detect arbitrary changes outside the descriptor. UDF remains inspection/eject only. Per-profile approvals are stored separately and can be explicitly revoked without deleting catalog entries or disc contents.

An approved ISO can register an executable relative path for direct Play. Only executable native Linux ELF files are accepted; the exact media ID and profile grant are checked at catalog registration, Play resolution, session launch and sandbox preparation. The read-only disc tree is exposed only for the session. A same-set disc can be registered as another edition. If the expected disc is absent or another disc in the set is mounted, Play reports the expected number and requires the user to retry; no automatic launch or disc swap occurs. Eject requests a normal UDisks unmount/eject and never forces a busy drive. Removing an optical catalog entry leaves the disc and all saves untouched.

The optical flow is not yet a full commercial disc-install lifecycle: no arbitrary vendor setup program, compatibility-runtime installer, DRM/activation bypass, in-game hot-swap continuation or UDF direct launch is claimed. If UDisks reports a busy mount, close the process using it and retry safe eject. An absent, unreadable or unsupported data volume reports a retryable mount error; audio-only media and drives that report no data sectors are not listed.

Not supported by this installer: arbitrary `.exe`/Windows installers, scripts, self-extracting installers, network installers, compatibility-runtime setup, dependency resolution, DRM/activation bypass, disk imaging, or automatic installer execution. A general third-party installer flow and original-disc install/play lifecycle remain T30.7/T30.8 coding gaps. No universal compatibility, gameplay, remote-only third-party setup, native build or physical-disc qualification is claimed here.

Focused executable validation: `python3 tests/test_portable_game_installer.py`, plus the existing Games provisioning and Steam adapter tests. Native C++/QML integration still requires the repository's Qt/CMake test environment.
