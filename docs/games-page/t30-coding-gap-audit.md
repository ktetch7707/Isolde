# T30.1–T30.9 coding-gap audit

This is a software-scope comparison against the original T30 requirements in `docs/agent-backlog.md` (entries T30.1–T30.9), not acceptance accounting. A missing VM, physical device, account or game is deferred verification; it is not counted here as a coding gap. This audit does not claim any T30 checkpoint complete.

| Requirement | Implemented code/evidence | Remaining coding gaps |
| --- | --- | --- |
| **T30.1 — support matrix, boundaries and budgets** | `games-page/GAMES_PAGE_PLAN.md`, `generation-coverage.md`, runtime definitions and fixture/provisioning records declare existing platform routes, licensing boundaries and some catalog/runtime limits. The free Webfest fixture is recorded. | The supported-generation target is still much broader than shipped adapters. A complete per-route architecture/installer/account/save/dependency matrix and numeric guest/VM resource budget are not implemented. Future unsupported routes need explicit product-facing status rather than being inferred from a generic runtime. |
| **T30.2 — one locally playable game and exact return** | Games registration, details, Play dispatch and native-session return are implemented. The checkpoint records a PSP Webfest keyboard-play/return journey. | The software still lacks an accepted, code-backed Xbox-controller route and a supported fixture/runtime contract proven end-to-end from the normal Games page. Save flush, disconnect/reconnect, crash, cancel/retry and precise focus restoration need fuller automation. Physical/gameplay acceptance is separately deferred. |
| **T30.3 — catalog, import, metadata, editions, backup** | Profile catalog, paged import preview/cancel, manual metadata/artwork, editions, organization, backup/restore and transactional catalog operations have focused tests and checkpoint evidence. | Catalog provenance and source/install/activity contracts are not yet uniformly typed across Steam, optical, local installs and emulators. Crash-consistency/write-failure coverage does not span every persistence boundary; deduplication and recovery need cross-source fixtures. |
| **T30.4 — shelves and scale** | All Games, platform/title queries, Favorites, recent/continue, manual/smart collections and edition selection are implemented in the shared remote UI. Catalog ceilings and paging are bounded. | The original 5/5,000 fixture, measured query/render budgets, remote/desktop parity and canonical-record consistency across every shelf have not all been proved in the current checkout. These are focused software/performance test gaps; no target hardware is required to add them. |
| **T30.5 — Steam lifecycle** | Managed-profile discovery/direct launch, external read-only library grants, App-ID revalidation and session handoff are implemented. Tests cover helper boundaries and simulated process identity. | Authenticated ownership, actual running-game detection across launchers, Steam client/game exit ownership, offline launch/save behavior and retry/reconnect contracts still need fuller code fixtures and user-owned-game acceptance. Installation is not entitlement proof. |
| **T30.6 — integrated emulator matrix** | Managed PPSSPP, Dolphin, PCSX2 and selected RetroArch/core setup, settings, firmware preflight and session adapters exist. | Sony/Microsoft/Nintendo generation coverage is incomplete: PlayStation, PS3/4, Vita; N64, DS/3DS, Wii U and Switch generations; original Xbox/360 and modern Xbox routes lack integrated verified adapters. Runtime artifact/license/dependency manifests, offline bundle completeness and recovery/update/rollback need remaining implementation. Existing runtime launchers do not satisfy these routes. |
| **T30.7 — local copies/installers** | T30 branch commits `64c6f34` and `95a69f1` add explicit profile-private install of a bounded inert ZIP bundle with a native Linux ELF entry point, runtime/destination review, archive hash revalidation, atomic staging/publication, cancellation and safe sandbox launch. A mounted optical drive can supply that bundle. | Arbitrary supported vendor/local installers, Windows/compatibility-runtime install, dependency/preflight resolution, useful progress reporting, post-install recovery/relink and broader installed-folder verification are absent. The portable ZIP is one intentionally narrow format, not a general PC installer solution. |
| **T30.8 — optical workflow** | A bounded read-only ISO9660/UDF observer, non-focus-stealing insertion/removal status, transient observation revalidation and explicit portable-bundle install are implemented. Synthetic classifier tests cover ready/replaced/missing states. No autorun is performed. | Durable media-set/disc identity and profile grant/association, ordinary disc Install/Play capability discovery, direct disc launch, original-disc-required prompts, multi-disc progression, wrong/unreadable media recovery, drive busy/eject semantics and owned uninstall are absent. This is only an optical bundle-install path, not the required full PC optical workflow. |
| **T30.9 — integrated software proof** | Component/native-session/input/QML tests exist for catalog, remote navigation, Steam grants, runtime adapters and portions of optical classification. The implementation documents distinguish simulation from actual gameplay. | Full production virtual optical protocol/UI matrices, 5,000-entry performance cases, cold-boot disconnected journeys, cross-runtime input/cancel/profile/session/save/crash coverage, and the two reference pairs are not all implemented or proved in this environment. Native C++/QML tests could not run here because CMake/Qt are unavailable; this is deferred verification, not a reason to stop coding. |

Focused available checks for the new installer slice: `python3 tests/test_portable_game_installer.py`, `python3 tests/test_steam_games.py`, `python3 tests/test_games_provisioning.py`, and `git diff --check`. Native/QML and installed-VM results are not claimed. Physical optical qualification remains H03, and Xbox-controller/gameplay qualification remains H02; neither changes the coding gaps above.
