# T30.1–T30.9 coding-gap audit

This is a software-scope comparison against the original T30 requirements in `docs/agent-backlog.md` (entries T30.1–T30.9), not acceptance accounting. A missing VM, physical device, account or game is deferred verification; it is not counted here as a coding gap. This audit does not claim any T30 checkpoint complete.

| Requirement | Implemented code/evidence | Remaining coding gaps |
| --- | --- | --- |
| **T30.1 — support matrix, boundaries and budgets** | `game-runtimes.json` explicitly lists integrated versus not-integrated generations, bound runtime packages/formats, Ubuntu/amd64 target and conservative support boundary. The support screen shows route status and enforced resource ceilings from shared `GameResourceLimits.h`: 50,000 entries, 50/page, 128 platforms, 256 collections, 32 editions/game, 1.6 million provenance records, 32 MiB backup, 128 MiB artwork restore and 512 MiB artwork store. Provisioning validation rejects overlapping or unknown routes. Licensing boundaries and the free Webfest fixture are recorded. | Unsupported generations still lack selected adapters; per-generation architecture/installer/account/save/dependency and guest disk/RAM/performance budgets are not completely implemented. The current bounds are catalog/archive limits, not a measured VM runtime-install budget. |
| **T30.2 — one locally playable game and exact return** | Games registration, details, Play dispatch and native-session return are implemented. The checkpoint records a PSP Webfest keyboard-play/return journey. Native game sessions from managed emulators, Steam, approved folders, Isolde installs and optical media request gamepad nodes only; bounded discovery filters recognized `eventN`/`jsN` nodes by controller key capabilities, exact Linux input major/minor mapping and non-symlink device paths. The native session host polls sysfs and adds only validated gamepad nodes inside the sandbox with a user-namespace-scoped `CAP_MKNOD`, dropped before game execution; detached helper-created nodes are removed only if device identity still matches. A non-focus-stealing notice reports endpoint changes and whether a new endpoint was exposed. Simulated tests cover endpoint attach/detach/reconnect summaries and strict input mapping. | The new node is made available inside the session, but the game/runtime must independently rescan devices; rescan behavior and cross-runtime disconnect/reconnect recovery still need production-boundary fixtures. Systems refusing user-namespace device-node creation fail closed to a relaunch notice. Exposing the whole input directory or broad mount/device capabilities remains disallowed. No accepted, code-backed Xbox-controller route is declared. Save flush, crash, cancel/retry and precise focus restoration need fuller automation. Physical/gameplay acceptance is separately deferred. |
| **T30.3 — catalog, import, metadata, editions, backup** | Profile catalog, paged import preview/cancel, manual metadata/artwork, editions, organization, backup/restore and transactional catalog operations have focused tests and checkpoint evidence. Details expose the current source classification and a separate append-only acquisition record for newly registered games/editions and confirmed Steam/folder imports. The record preserves original source kind, origin action, source reference, locator SHA-256 fingerprint and timestamp through metadata edits, removal and v4 backup/restore; SQLite triggers reject update/delete, and restore rejects conflicts with an existing immutable record and rejects entity-type mismatches for catalog entries present in the archive. Manual registration is distinguished from Steam/folder import and portable installation. A focused regression verifies folder import deduplicates a manually registered installation without overwriting user metadata or provenance. A recovery action now revalidates the full manifest/inventory of an orphaned private managed install before adding a missing catalog record. The QML identifies legacy entries as unrecorded and states that neither source classification nor provenance proves license/ownership. The 2026-11-09 artwork recovery slice checks every retained pre-restore SQLite copy before deleting managed artwork and removes only verified unreferenced crash orphans on catalog reopen; see [catalog/artwork recovery](catalog-artwork-recovery-2026-11-09.md). | Provenance describes the registered locator, not verified bytes, a chain of custody or ownership. Existing legacy entries remain unrecorded rather than receiving fabricated history. Crash/write-failure coverage remains incomplete outside the managed-artwork/reference boundary, including archive creation failures, broader catalog mutations and power-loss/installed-VM recovery. The focused Qt regression has not run in this environment. |
| **T30.4 — shelves and scale** | All Games, platform/title queries, Favorites, recent/continue, manual/smart collections and edition selection are implemented in the shared remote UI. Smart collections support parameterized title/platform/franchise substring rules, exact profile-tag rules, Favorites and recently-played membership/order; create/edit is D-pad-operable and filter rules are non-executable data. New franchise/tag/recent rules have remote D-pad choice coverage and catalog backup/restore coverage. Next-page availability now probes the actual next result page and obeys the catalog limit supplied by `GameLibrary`, including exact-full-page and 50,000-entry boundaries. `games_ui.cpp` seeds 5,000 catalog rows for paging and has a 50,000-entry boundary fixture; the collection fixture covers added rules, edits, profile-database isolation, persistence and membership after removal. | The new C++ fixtures could not run here without Qt/CMake. Measured query/render budgets, remote/desktop parity and canonical-record consistency across every shelf remain unproved. These are focused software/performance test gaps; no target hardware is required to add them. |
| **T30.5 — Steam lifecycle** | Managed-profile discovery/direct launch, external read-only library grants, App-ID revalidation, session handoff, an explicit account/offline setup route, and bounded client/install-manifest preflight are implemented. The preflight reports client availability and local manifest status without claiming entitlement. Version-2 lifecycle state separates normal/canceled/incomplete/recovery-required process return from exit, local-save and Cloud facts; a provider failure stops only the tagged game processes for this launch before ending its client. Controlled-provider and real tagged-process fixtures cover failure/return cleanup and profile-save preservation. | The shipped provider still cannot authenticate ownership/account/offline state or prove game exit/save/sync outcomes; these remain unknown without authoritative Steam integration. Actual running-game detection across launchers, offline launch/save behavior and retry/reconnect contracts need fuller production-boundary coverage and user-owned-game acceptance. Installation is not entitlement proof. |
| **T30.6 — integrated emulator matrix** | Managed PPSSPP, Dolphin, PCSX2 and selected RetroArch/core setup, settings, firmware preflight and session adapters exist. Signed offline dependency bundles bind exact package versions, hashes, the manifest and authenticated apt-index metadata; install avoids network/index refresh and durable checkpoints support rollback/recovery. Follow-up update flow simulates exact apt targets, rejects removals or unrelated package changes, requires signed prior archives, captures a signed rollback set and recovers interrupted updates. | Sony/Microsoft/Nintendo generation coverage remains incomplete: PlayStation, PS3/4, Vita; N64, DS/3DS, Wii U and Switch generations; original Xbox/360 and modern Xbox routes lack integrated adapters. Actual Ubuntu 26.04 bundle production, disconnected appliance installation, package rollback and gameplay/input acceptance remain unverified; these verification gaps do not imply missing update code or support for unintegrated generations. |
| **T30.7 — local copies/installers** | T30 branch commits `64c6f34` and `95a69f1` add explicit profile-private install of bounded inert ZIP, USTAR, gzip-USTAR and bzip2-USTAR bundles with a native Linux ELF entry point, runtime/destination review, archive hash revalidation, atomic staging/publication, cancellation and safe sandbox launch. XZ-USTAR is explicitly rejected because its decoder-memory limit cannot be bounded with the available Python tarfile interface. The same flow also accepts a single structurally checked x86-64 Linux ELF executable; only that file is copied, not adjacent assets or dependencies. A mounted optical drive can supply these sources. A verified orphaned managed install can be re-registered after full marker/inventory/hash/ELF verification; pending uninstall recovery remains separate and never deletes files. Profile-approved Windows PE files have an asynchronous, cancelable, bounded format/architecture/full-SHA-256 inspection path; it explicitly does not run or install them and makes no publisher, ownership or safety claim. Separately confirmed uninstall verifies managed file inventory and hashes, uses no-follow directory traversal, preserves newly arrived unowned files, and keeps profile saves outside the removed subtree. | Arbitrary vendor/local installers, Windows/compatibility-runtime execution or installation, and local game-package dependency resolution remain absent. Uninstall still cannot atomically defend against malicious concurrent replacement; external writers must be stopped during cleanup. Catalog-only removal for other sources preserves files. |
| **T30.8 — optical workflow** | A bounded ISO9660/UDF observer, unmounted-media read-only UDisks mount, profile-scoped full-content identity grant, ISO9660 volume/set identity and UDF single-disc identity, non-focus-stealing insertion/removal status, read-only native ELF Play, same-set discs as editions, missing/wrong-disc retry messages, explicit portable-bundle install, verified managed-package uninstall and non-forced UDisks safe eject are implemented. Direct Play revalidates the selected media identity and mount observation before sandbox launch; all optical content is mounted read-only. Virtual D-Bus seams exercise read-only mount options, missing media, malformed mountpoint and service error handling, plus busy-unmount refusal and normal unmount → drive lookup → eject with no force method. Catalog removal never deletes physical media or saves. | Full-content hashes do not distinguish bit-identical copies, and cached hashes do not detect changes without a new disk sequence. UDF has no multi-disc set grouping. Game-level scripted prompts while a running title asks for a swap, multi-disc guest swap handling without relaunch, active-session eject arbitration beyond normal busy refusal, device-specific mount diagnostics and physical-drive acceptance remain incomplete. |
| **T30.9 — integrated software proof** | Component/native-session/input/QML tests exist for catalog, remote navigation, Steam grants, runtime adapters and portions of optical classification. Safe eject D-Bus behavior, read-only mount recovery, controller discovery and simulated attach/detach/reconnect summaries, 5,000-game paging, the catalog-cap page boundary and injected catalog-restore rollback have focused C++ tests. Focused Python suites pass: provisioning 32, Steam 23, optical executor 3, portable installer 23. Implementation documents distinguish simulation from actual gameplay. | Full production virtual optical protocol/UI matrices, 5,000-entry measured performance budgets, cold-boot disconnected journeys, cross-runtime input/cancel/profile/session/save/crash coverage, and the two reference pairs are not all implemented or proved. Native C++/QML tests could not run here because CMake/Qt are unavailable; this is deferred verification, not a reason to stop coding. |

Focused Steam check: `python3 tests/test_steam_games.py` passes 25 tests. The other available focused checks are `python3 tests/test_portable_game_installer.py`, `python3 tests/test_games_provisioning.py`, and `python3 tests/test_optical_exec.py`. Native C++/QML and installed-VM results are not claimed. Physical optical qualification remains H03, and Xbox-controller/gameplay qualification remains H02; neither changes the coding gaps above.

The no-exec optical adapter stages bounded ELF files, including libraries, in a private session tree while linking non-ELF data to the read-only disc. A compiled ELF fixture exercises `$ORIGIN/../lib`; separate checks confirm libraries are copied rather than mapped from the no-exec disc. This does not close the remaining optical or installer gaps.

Interrupted post-catalog managed uninstall cleanup can now be explicitly resumed from the remote recovery screen. It verifies all remaining owned files and refuses modified or unowned content; a missing ownership marker still requires manual inspection. Other installer and cross-source recovery requirements remain open.
