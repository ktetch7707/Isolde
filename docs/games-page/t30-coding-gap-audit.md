# T30.1–T30.9 coding-gap audit

This is a software-scope comparison against the original T30 requirements in `docs/agent-backlog.md` (entries T30.1–T30.9), not acceptance accounting. A missing VM, physical device, account or game is deferred verification; it is not counted here as a coding gap. This audit does not claim any T30 checkpoint complete.

| Requirement | Implemented code/evidence | Remaining coding gaps |
| --- | --- | --- |
| **T30.1 — support matrix, boundaries and budgets** | `games-page/GAMES_PAGE_PLAN.md`, `generation-coverage.md`, runtime definitions and fixture/provisioning records declare existing platform routes, licensing boundaries and some catalog/runtime limits. The free Webfest fixture is recorded. | The supported-generation target is still much broader than shipped adapters. A complete per-route architecture/installer/account/save/dependency matrix and numeric guest/VM resource budget are not implemented. Future unsupported routes need explicit product-facing status rather than being inferred from a generic runtime. |
| **T30.2 — one locally playable game and exact return** | Games registration, details, Play dispatch and native-session return are implemented. The checkpoint records a PSP Webfest keyboard-play/return journey. Native game sessions from managed emulators, Steam, approved folders, Isolde installs and optical media request gamepad nodes only; an extracted bounded capability classifier distinguishes BTN_GAMEPAD key bits from keyboard-only, malformed and oversized bitmaps, with focused tests. | The software still lacks an accepted, code-backed Xbox-controller route and a supported fixture/runtime contract proven end-to-end from the normal Games page. Save flush, disconnect/reconnect, crash, cancel/retry and precise focus restoration need fuller automation. Physical/gameplay acceptance is separately deferred. |
| **T30.3 — catalog, import, metadata, editions, backup** | Profile catalog, paged import preview/cancel, manual metadata/artwork, editions, organization, backup/restore and transactional catalog operations have focused tests and checkpoint evidence. Details now expose a typed current-source classification (Steam App ID, optical identity, managed install, approved folder or runtime entry) derived from persisted locators, and clearly state it is not license/ownership proof; tests cover Steam/runtime classifications and preservation of the derived locator through catalog backup/restore. | Classification is inferred from current locators, not an immutable acquisition history; it is not yet a uniform persisted source/install/activity contract across Steam, optical, local installs and emulators. Crash-consistency/write-failure coverage does not span every persistence boundary; deduplication and recovery need cross-source fixtures. |
| **T30.4 — shelves and scale** | All Games, platform/title queries, Favorites, recent/continue, manual/smart collections and edition selection are implemented in the shared remote UI. Smart collections support parameterized title/platform/franchise substring rules, exact profile-tag rules, Favorites and recently-played membership/order; create/edit is D-pad-operable and filter rules are non-executable data. New franchise/tag/recent rules have remote D-pad choice coverage. Next-page availability now probes the actual next result page and obeys the catalog limit supplied by `GameLibrary`, including exact-full-page and 50,000-entry boundaries. `games_ui.cpp` seeds 5,000 catalog rows for paging and has a 50,000-entry boundary fixture; the collection fixture covers added rules, edits, persistence and membership after removal. | The new C++ fixtures could not run here without Qt/CMake. Measured query/render budgets, remote/desktop parity and canonical-record consistency across every shelf remain unproved. These are focused software/performance test gaps; no target hardware is required to add them. |
| **T30.5 — Steam lifecycle** | Managed-profile discovery/direct launch, external read-only library grants, App-ID revalidation and session handoff are implemented. Tests cover helper boundaries and simulated process identity. | Authenticated ownership, actual running-game detection across launchers, Steam client/game exit ownership, offline launch/save behavior and retry/reconnect contracts still need fuller code fixtures and user-owned-game acceptance. Installation is not entitlement proof. |
| **T30.6 — integrated emulator matrix** | Managed PPSSPP, Dolphin, PCSX2 and selected RetroArch/core setup, settings, firmware preflight and session adapters exist. | Sony/Microsoft/Nintendo generation coverage is incomplete: PlayStation, PS3/4, Vita; N64, DS/3DS, Wii U and Switch generations; original Xbox/360 and modern Xbox routes lack integrated verified adapters. Runtime artifact/license/dependency manifests, offline bundle completeness and recovery/update/rollback need remaining implementation. Existing runtime launchers do not satisfy these routes. |
| **T30.7 — local copies/installers** | T30 branch commits `64c6f34` and `95a69f1` add explicit profile-private install of bounded inert ZIP and uncompressed USTAR bundles with a native Linux ELF entry point, runtime/destination review, archive hash revalidation, atomic staging/publication, cancellation and safe sandbox launch. A mounted optical drive can supply either bundle. The follow-up adds a separately confirmed uninstall that checks an exact managed-file inventory and per-file hashes; modified/unowned files block deletion, and profile saves remain outside the removed subtree. | Arbitrary vendor/local installers, compressed tar/other archive variants, Windows/compatibility-runtime install and dependency/preflight resolution remain absent. Safe uninstall applies only to verified Isolde-managed bundle installs; catalog-only removal for other sources still preserves files. |
| **T30.8 — optical workflow** | A bounded ISO9660/UDF observer, unmounted-media read-only UDisks mount, profile-scoped ISO descriptor-fingerprint grant, ISO9660 volume/set identity, non-focus-stealing insertion/removal status, read-only native ELF Play, same-set discs as editions, missing/wrong-disc retry messages, explicit portable-bundle install, verified managed-package uninstall and non-forced UDisks safe eject are implemented in the follow-up. Direct Play revalidates the selected media identity before sandbox launch; all optical content is mounted read-only. Virtual D-Bus seams exercise read-only mount options, missing media, malformed mountpoint and service error handling, plus busy-unmount refusal and normal unmount → drive lookup → eject with no force method. Catalog removal never deletes physical media or saves. | UDF has no identity/direct Play. Descriptor fingerprints are not full-content hashes, cannot distinguish bit-identical copies, and do not detect arbitrary changes outside the PVD. Game-level scripted prompts while a running title asks for a swap, multi-disc guest swap handling without relaunch, active-session eject arbitration beyond normal busy refusal, device-specific mount diagnostics and physical-drive acceptance remain incomplete. |
| **T30.9 — integrated software proof** | Component/native-session/input/QML tests exist for catalog, remote navigation, Steam grants, runtime adapters and portions of optical classification. Safe eject D-Bus behavior, read-only mount recovery, gamepad capability filtering, 5,000-game paging and the catalog-cap page boundary now have focused C++ tests. The implementation documents distinguish simulation from actual gameplay. | Full production virtual optical protocol/UI matrices, 5,000-entry measured performance budgets, cold-boot disconnected journeys, cross-runtime input/cancel/profile/session/save/crash coverage, and the two reference pairs are not all implemented or proved in this environment. Native C++/QML tests could not run here because CMake/Qt are unavailable; this is deferred verification, not a reason to stop coding. |

Focused available checks for the new installer slice: `python3 tests/test_portable_game_installer.py`, `python3 tests/test_steam_games.py`, `python3 tests/test_games_provisioning.py`, and `git diff --check`. Native/QML and installed-VM results are not claimed. Physical optical qualification remains H03, and Xbox-controller/gameplay qualification remains H02; neither changes the coding gaps above.
