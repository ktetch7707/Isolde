# T30.1–T30.9 coding-gap audit

This is a software-scope comparison against the original T30 requirements in `docs/agent-backlog.md` (entries T30.1–T30.9), not acceptance accounting. A missing VM, physical device, account or game is deferred verification; it is not counted here as a coding gap. This audit does not claim any T30 checkpoint complete.

| Requirement | Implemented code/evidence | Remaining coding gaps |
| --- | --- | --- |
| **T30.1 — support matrix, boundaries and budgets** | `game-runtimes.json` explicitly lists integrated versus not-integrated generations, bound runtime packages/formats, Ubuntu/amd64 target and conservative support boundary. The support screen shows route status and enforced resource ceilings from shared `GameResourceLimits.h`: 50,000 entries, 50/page, 128 platforms, 256 collections, 32 editions/game, 1.6 million provenance records, 32 MiB backup, 128 MiB artwork restore and 512 MiB artwork store. Provisioning validation rejects overlapping or unknown routes. Licensing boundaries and the free Webfest fixture are recorded. | Unsupported generations still lack selected adapters; per-generation architecture/installer/account/save/dependency and guest disk/RAM/performance budgets are not completely implemented. The current bounds are catalog/archive limits, not a measured VM runtime-install budget. |
| **T30.2 — one locally playable game and exact return** | Games registration, details, Play dispatch and native-session return are implemented. The checkpoint records a PSP Webfest keyboard-play/return journey. Native game sessions from managed emulators, Steam, approved folders, Isolde installs and optical media request gamepad nodes only; bounded discovery filters recognized `eventN`/`jsN` nodes by controller key capabilities and refuses symlinked device paths. The native session host now polls sysfs and adds only validated gamepad event nodes inside the sandbox with a user-namespace-scoped `CAP_MKNOD`, dropped before game execution; detached helper-created nodes are removed only if device identity still matches. A non-focus-stealing notice reports endpoint changes and whether a new endpoint was exposed. Simulated tests cover endpoint attach/detach/reconnect summaries and strict input major/minor mapping. | The new node is made available inside the session, but the game/runtime must independently rescan devices; rescan behavior and cross-runtime disconnect/reconnect recovery still need production-boundary fixtures. Systems refusing user-namespace device-node creation fail closed to a relaunch notice. Exposing the whole input directory or broad mount/device capabilities remains disallowed. No accepted, code-backed Xbox-controller route is declared. Save flush, crash, cancel/retry and precise focus restoration need fuller automation. Physical/gameplay acceptance is separately deferred. |
| **T30.3 — catalog, import, metadata, editions, backup** | Profile catalog, paged import preview/cancel, manual metadata/artwork, editions, organization, backup/restore and transactional catalog operations have focused tests and checkpoint evidence. Details expose the current source classification and a separate append-only acquisition record for newly registered games/editions and confirmed Steam/folder imports. The record preserves original source kind, origin action, source reference, locator SHA-256 fingerprint and timestamp through metadata edits, removal and v4 backup/restore; SQLite triggers reject update/delete, and restore rejects conflicts with an existing immutable record and rejects entity-type mismatches for catalog entries present in the archive. Manual registration is distinguished from Steam/folder import and portable installation. A focused regression verifies folder import deduplicates a manually registered installation without overwriting user metadata or provenance. The QML identifies legacy entries as unrecorded and states that neither source classification nor provenance proves license/ownership. | Provenance describes the registered locator, not verified bytes, a chain of custody or ownership. Existing legacy entries remain unrecorded rather than receiving fabricated history. Crash-consistency/write-failure coverage does not span every persistence boundary; cross-source recovery still needs fixtures. |
| **T30.4 — shelves and scale** | All Games, platform/title queries, Favorites, recent/continue, manual/smart collections and edition selection are implemented in the shared remote UI. Smart collections support parameterized title/platform/franchise substring rules, exact profile-tag rules, Favorites and recently-played membership/order; create/edit is D-pad-operable and filter rules are non-executable data. New franchise/tag/recent rules have remote D-pad choice coverage and catalog backup/restore coverage. Next-page availability now probes the actual next result page and obeys the catalog limit supplied by `GameLibrary`, including exact-full-page and 50,000-entry boundaries. `games_ui.cpp` seeds 5,000 catalog rows for paging and has a 50,000-entry boundary fixture; the collection fixture covers added rules, edits, profile-database isolation, persistence and membership after removal. | The new C++ fixtures could not run here without Qt/CMake. Measured query/render budgets, remote/desktop parity and canonical-record consistency across every shelf remain unproved. These are focused software/performance test gaps; no target hardware is required to add them. |
| **T30.5 — Steam lifecycle** | Managed-profile discovery/direct launch, external read-only library grants, App-ID revalidation, session handoff, an explicit account/offline setup route, and bounded client/install-manifest preflight are implemented. The preflight reports client availability and local manifest status without claiming entitlement. Tests cover helper boundaries and simulated process identity. | Authenticated ownership, actual running-game detection across launchers, Steam client/game exit ownership, offline launch/save behavior and retry/reconnect contracts still need fuller code fixtures and user-owned-game acceptance. Installation is not entitlement proof. |
| **T30.6 — integrated emulator matrix** | Managed PPSSPP, Dolphin, PCSX2 and selected RetroArch/core setup, settings, firmware preflight and session adapters exist. Signed offline dependency bundles bind exact package versions, hashes, the manifest and authenticated apt-index metadata; install avoids network/index refresh and durable checkpoints support rollback/recovery. Follow-up update flow simulates exact apt targets, rejects removals or unrelated package changes, requires signed prior archives, captures a signed rollback set and recovers interrupted updates. | Sony/Microsoft/Nintendo generation coverage remains incomplete: PlayStation, PS3/4, Vita; N64, DS/3DS, Wii U and Switch generations; original Xbox/360 and modern Xbox routes lack integrated adapters. Actual Ubuntu 26.04 bundle production, disconnected appliance installation, package rollback and gameplay/input acceptance remain unverified; these verification gaps do not imply missing update code or support for unintegrated generations. |
| **T30.7 — local copies/installers** | T30 branch commits `64c6f34` and `95a69f1` add explicit profile-private install of bounded inert ZIP, USTAR and gzip-USTAR bundles with a native Linux ELF entry point, runtime/destination review, archive hash revalidation, atomic staging/publication, cancellation and safe sandbox launch. A mounted optical drive can supply these bundles. Profile-approved Windows PE files now have an asynchronous, cancelable, bounded format/architecture/full-SHA-256 inspection path; it explicitly does not run or install them and makes no publisher, ownership or safety claim. Separately confirmed uninstall verifies managed file inventory and hashes, uses no-follow directory traversal, preserves newly arrived unowned files, and keeps profile saves outside the removed subtree. | Arbitrary vendor/local installers, Windows/compatibility-runtime execution or installation, and local game-package dependency resolution remain absent. Uninstall still cannot atomically defend against malicious concurrent replacement; external writers must be stopped during cleanup. Catalog-only removal for other sources preserves files. |
| **T30.8 — optical workflow** | A bounded ISO9660/UDF observer, unmounted-media read-only UDisks mount, profile-scoped ISO descriptor-fingerprint grant, ISO9660 volume/set identity, non-focus-stealing insertion/removal status, read-only native ELF Play, same-set discs as editions, missing/wrong-disc retry messages, explicit portable-bundle install, verified managed-package uninstall and non-forced UDisks safe eject are implemented in the follow-up. Direct Play revalidates the selected media identity before sandbox launch; all optical content is mounted read-only. Virtual D-Bus seams exercise read-only mount options, missing media, malformed mountpoint and service error handling, plus busy-unmount refusal and normal unmount → drive lookup → eject with no force method. Catalog removal never deletes physical media or saves. | UDF has no identity/direct Play. Descriptor fingerprints are not full-content hashes, cannot distinguish bit-identical copies, and do not detect arbitrary changes outside the PVD. Game-level scripted prompts while a running title asks for a swap, multi-disc guest swap handling without relaunch, active-session eject arbitration beyond normal busy refusal, device-specific mount diagnostics and physical-drive acceptance remain incomplete. |
| **T30.9 — integrated software proof** | Component/native-session/input/QML tests exist for catalog, remote navigation, Steam grants, runtime adapters and portions of optical classification. Safe eject D-Bus behavior, read-only mount recovery, controller discovery and simulated attach/detach/reconnect summaries, 5,000-game paging, the catalog-cap page boundary and injected catalog-restore rollback have focused C++ tests. Focused Python suites pass: provisioning 32, Steam 23, optical executor 3, portable installer 23. Implementation documents distinguish simulation from actual gameplay. | Full production virtual optical protocol/UI matrices, 5,000-entry measured performance budgets, cold-boot disconnected journeys, cross-runtime input/cancel/profile/session/save/crash coverage, and the two reference pairs are not all implemented or proved. Native C++/QML tests could not run here because CMake/Qt are unavailable; this is deferred verification, not a reason to stop coding. |

Focused available checks: `python3 tests/test_portable_game_installer.py`, `python3 tests/test_steam_games.py`, `python3 tests/test_games_provisioning.py`, `python3 tests/test_optical_exec.py`, Python bytecode compilation for changed tools, JSON validation and `git diff --check`. Native C++/QML and installed-VM results are not claimed. Physical optical qualification remains H03, and Xbox-controller/gameplay qualification remains H02; neither changes the coding gaps above.
