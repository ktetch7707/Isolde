## Implementation

- `src/home/StudioSafety.cpp` extends the existing `StudioSession` owner. Health findings retain stable page/component/property locations, distinguish nonblocking design/availability findings, and keep intentional empty components usable. - `qml/PageStudioView.qml` keeps the actual renderer as the primary workspace. The named **Try, versions & safety** menu contains secondary interaction testing, real/long-title/missing-art/empty/50-item scenarios, versions and a session lock. Interaction follows draft internal page actions and explains intercepted external actions. Back restores page, component, nested scope, header selection, toolbar state, per-page focus map and editor viewport. Synthetic values enter only renderer inputs; the session document, Apply and export retain authored data.
- Review & Apply lists every affected page/settings group, routes health findings to their component/property, and applies the whole document once. Failure retains the draft and offers Retry, Continue, Discard, saved-versus-draft comparison, a named local draft copy and explicit destructive reload confirmation. Reload validates readable saved bytes before discarding the current draft and never rewrites on read.
- Named and automatic pre-Apply snapshots use a profile-local, versioned atomic archive beside the layout. Retention is ten snapshots / 40 MiB of layout data, with at most 128 shared content-addressed images / 64 MiB decoded artwork (132 MiB serialized-file ceiling). Snapshots preserve privately staged artwork, deduplicate shared images, prune unreferenced archive images, and never package reference overlays, accounts, device settings or media. Versions can be compared, restored for Current page or Whole interface as one reversible draft transaction, or explicitly deleted. Malformed archives, symlink/redirected locations, unsafe artwork and unavailable assets fail visibly without replacing the current draft. Existing original-v1 downgrade backup behavior stays in the shared save pipeline.
- `ProfileManager` owns persisted household edit/install/custom-destination controls, with unrestricted defaults for older profiles. Invalid policy data stays on disk, denies editing/installing with a recovery explanation, and is replaced only by an explicit policy edit. Settings and designated Home remain recovery routes. A dirty Studio session refuses profile switching/restriction until Apply or Discard. Session commands, preview/import, Apply and outgoing-profile operations enforce the policy/lock; legacy layout save/reset/skin Apply, Store installation/download completion and destination routing also check their existing authorities. These are accidental-change controls, not authentication or a sandbox for external apps/purchases.
- Reference overlay privacy and existing scrolling/removed-origin recovery use the shared session and renderer contracts. Concurrent T22/T24 implementation remains its owners' work and is not accepted by this change.
