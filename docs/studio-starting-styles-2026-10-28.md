# T21.8/T21.11 — editable starting styles

Add component now offers visual starting styles for Button, Image and Text. Buttons provide standard, round icon, wide tile and poster shapes. Images provide landscape, poster and full-artwork fit. Text provides body and heading styles. The previews use the production `HomeCard` with packaged preset presentation and the variant overrides; no screenshots, executable templates or new renderer branches are involved.

`componentVariants` in `studio-defaults.json` defines every name, description, initial span and presentation value. The options boundary accepts only the three supported families, up to eight styles per family, unique safe identities, bounded strings, a two-field span and a valid complete component. The native prototype command accepts a registered style identity, then creates an ordinary editable component. It stores the resulting placement and presentation, never a magic style identifier or code. Unknown styles/types and incompatible data are refused before history or persistence changes.

Selection leads through the existing content/action choice and full-page ghost placement. Back returns to the exact original family, including its catalog position. App-picker cancellation now has that same exact-family behavior. Accepting placement remains one draft transaction; selecting or cancelling a starting style writes no applied data. Existing calls without a style retain their prior preset behavior.

Host checks pass: 278 extracted JavaScript functions and 89 handlers compile, and actual catalog methods pass style selection, typed configuration and exact cancellation-origin checks. Settings remain below 64 KiB. [The retained result](quality/studio-starting-styles-host-20261028.json) lists source hashes and its limited scope. `git diff --check` passes. This is not QML type checking, native compilation or a visual/user acceptance claim.

New native case `studioStartingStylesAreValidatedDraftData` checks every packaged style, resulting ordinary component/span/presentation, unchanged draft/history, unknown/wrong-family refusal and oversized packaged span rejection. New QML case `test_starting_styles_remote_cancel_and_pointer_parity` checks remote and pointer selection through the common prototype and unchanged applied bytes. `studioCatalogAndContextualInspector` now traverses the real starting-style step. Native/QML execution and both visual recreation/reset pairs remain delegated to the testing agent, using the bounded VM runner and stopping at its first named failure.

This completes this starting-style implementation batch, not the broad T21 gate. External app-history provider capability/account proof is still unavailable; Kodi is the default local history authority. Native/installed/visual and uncoached usability acceptance remain open.
