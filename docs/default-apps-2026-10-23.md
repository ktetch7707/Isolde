# Default apps and Steam provisioning

The user requests downloaded defaults: Kodi, a SmartTube-like Linux YouTube client, Spotify, CBC Gem, Prime Video, Disney+, Paramount+, Crunchyroll, Netflix, Peacock and Steam. Their clarification permits a substitute with API/ad controls. FreeTube is the selected native client; its optional Invidious and SponsorBlock controls remain user choices. Steam Big Picture owns games, downloads and licenses. Isolde does not introduce a parallel Steam library database.

## Implementation

`config/default-apps.json` declares the default set and native launch recipes. The appliance installer downloads native Kodi, FreeTube, Spotify, Steam and Google Chrome. Seven provider web apps use dedicated Chrome profiles and official provider URLs. They require applicable accounts, regions and subscriptions; registration or a loaded website is not evidence of paid playback.

Native executables must exist before activation publishes installed state. Existing package failures and user layouts are preserved. A completed first-install receipt prevents startup from reinstalling apps the user later removes. Provider artwork downloads are bounded, content-addressed and performed during explicit provisioning, not Home startup. Download/activation failures surface rather than silently registering missing native clients.

The bounded VM runner adds `Provision` for an explicitly deployed, fully passing snapshot. It verifies the guest identity, leases/stops the service, installs clients, records receipts, verifies layout hashes and restores the service. Existing guest apt-get/dpkg delegation is used without changing sudo policy or granting a root Python script. Fresh appliance setup retains its normal root dependency-install phase.

Legacy Steam component references resolve through validated app compatibility IDs, preserving stored layout bytes. The packaged default now launches the real Steam app. The Games page remains a configurable app collection; selecting Steam opens its Big Picture library.

Desktop portal identity now uses `org.isolde.Isolde`, a public desktop entry and the portal Registry handshake on a dedicated bus connection. Private DBus tests cover registration failure, cancellation/retry, restart, denial and safe return. Actual compositor permission is a separate installed acceptance gate.

## Security compatibility proposal — blocked, not applied

Automatic approval review rejects a proposed root-owned Isolde bubblewrap copy plus application-specific unconfined AppArmor profile allowing nested user namespaces. Its stated reason is that this persistently weakens the guest security boundary and is not covered by the Steam testing authorization. The patch was rejected before any file was changed. It is not installed, executed or retried through another mechanism. The existing private-home isolation, capability drop and global Ubuntu bwrap policy remain in place.

This exception would permit native clients to create their own nested sandboxes but reduce Ubuntu's current restriction for processes launched through that wrapper. Explicit user approval is required before pursuing that route; administrator authentication may also be required. Product and installed native-client acceptance remain open. Downloads, launcher registration and passing isolated native tests do not waive this real runtime failure.
