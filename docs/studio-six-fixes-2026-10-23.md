# User-requested six repairs

The user explicitly requested supplied app icons, Games/Music pages, Guide routing, a top-right Web search toggle and real Desktop handoff. These authorize the affected T21/T11/T28/T12 slices while the original prerequisite and standing acceptance gates stay open. No task percentage changes are claimed yet.

## Current implementation, pending integration verification

- **Icons:** AppRegistry resolves app-supplied desktop Icon metadata or installed icon themes into bounded, content-addressed, profile-scoped PNG caches. The official local YouTube vector is declarative app metadata. Collection cards and ordinary launchers use the managed icon; user artwork still takes precedence. No startup network icon fetches. Native fixture verifies metadata resolution, managed cache identity, launcher binding and unsafe/remote rejection.
- **Music:** a real editable page has a registered Kodi music-library component, album-to-track navigation, local song-ID playback and music-app collection. Kodi owns metadata, files and the audio player. Music queries are bounded at 50 and do not disclose arbitrary file fields. Local file/readability and ownership checks precede song playback; no streaming adapter is implied.
- **Games:** an editable page uses a validated app-group filter over real launchable registry apps, with dynamic membership and a Store route when empty. An existing-Steam launcher is available in the catalog; its description explicitly says registering it does not install Steam or games. No game collection database or pretend game session is introduced.
- **Guide:** the Home route opens a page with a registered PVR-channel component, current/next programme metadata and bounded paging. It reads configured Kodi TV channels; hidden entries are excluded and the playback bridge rejects hidden/locked channels before Player.Open. Empty/unavailable states identify the absent PVR configuration. This does not complete the planned offline PseudoTV scheduler or full EPG task.
- **Search:** Web search is a real accessible header switch, separate from results/count/index. Query/switch/results/keyboard D-pad paths preserve query and origin. Preference captures the active profile and retains its previous visible value on atomic-sync failure. ON with no provider is truthful header status; no fake provider result or external search endpoint.
- **Desktop:** the placeholder route is replaced by a compositor GlobalShortcuts portal session. Isolde stays visible until a return shortcut is actually granted, then reveals the OS desktop and supplies an independent Return window. Denial/cancel/timeouts, stale replies and revoked sessions cannot strand the shell. Profile teardown closes the session. Qt's existing DBus module is used; no host toolchain/settings/service changes. The installer supplies a stable Isolde desktop identity. Actual VM/compositor permission and handoff verification remain pending.

Updated preset pages are opt-in data. Stored user layouts are never rewritten on startup. The explicit “Update starter pages” operation previews only unchanged starter links, adds their missing pages and keeps custom links, existing pages and authored presentation. It commits through the existing validated atomic Studio transaction; cancellation writes nothing.
