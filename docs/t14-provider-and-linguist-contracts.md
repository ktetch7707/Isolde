# T14 provider and Linguist implementation notes

## Discovery provider decision

The conservative metadata/provider-listing choice is **The Movie Database (TMDB) API v3**. The production adapter uses the explicit `/search/multi` route for movie/TV identity, then `/{movie|tv}/{id}/watch/providers` for a user-selected two-letter region. It sends a request only after the profile's persistent Web preference is ON and a query of at least two characters is open. The read token is supplied through `ISOLDE_TMDB_READ_TOKEN`; it is not persisted in settings or logged. Missing configuration produces a visible local-only state and makes no request.

Searches are bounded to 200 input characters, a 2 MiB response, and 20 accepted results. The region is persisted under the active profile's Search settings; the remote offers common-region D-pad cycling and a remote keyboard for any two-letter ISO region code. Each result gets a request-time UTC timestamp and a media-type/provider-ID/year identity so remakes and separately identified releases are not merged. Results are memory-only; switching Web OFF, closing Search, changing region, or beginning another query aborts in-flight replies and clears old results. Provider listings are observations, not proof of subscription, playback rights, account access, or current availability. The UI does not claim entitlement or launch a third-party service.

Attribution is shown as TMDB metadata and the UI carries the required disclaimer: “This product uses the TMDB API but is not endorsed or certified by TMDB.” Production distribution must continue to follow TMDB's current API/attribution terms and include any required official attribution asset. The text attribution is implemented, but the official visual attribution asset and final licensing/package review remain coding gaps. Provider responses are exercised using a local HTTP fixture; no live account or credentials are required by the focused contract test.

## Offline subtitle choices

The existing-SRT translation adapter invokes **Argos Translate CLI** once per cue with `--from-lang`, `--to-lang`, and `--text`. The conservative audio-generation path invokes **whisper.cpp CLI** in local translate mode using an already-present multilingual `.bin` model. Both processes are started directly with argument vectors; there is no shell command construction, media upload, package installation, or model download. Missing executables/language packs/models fail visibly and retain the input.

Only a specifically selected UTF-8 SRT or media file is queued; no whole-library jobs are created. The explicit queue is bounded to 16 jobs. SRT input is bounded (8 MiB / 10,000 cues / 16 KiB per cue), cue headers/timecodes are preserved for translation, results are written atomically to a non-colliding language-suffixed file, and a provenance sidecar records tool, source hash, languages, UTC creation time, offline-only processing and review requirement. If the media folder is not writable, output is stored under Isolde's managed cache. Cancelled or failed work does not replace a source or completed output. Completed SRT can be reviewed and atomically edited before Kodi is asked to load it through its supported local player API. Forgetting a queue record never deletes its output or provenance.

Machine translation/transcription quality is not certified. Outputs require review. The language model, Argos package and Whisper model remain operator-installed offline prerequisites; this slice intentionally does not ship model downloads or credentials. Online subtitle repositories, `.ass` translation, language-pack management, library-wide jobs, measured language quality, and automated speech alignment are not implemented. The source must also be a local media file, not a stream.

## Coding/verification status

This note records code contracts and provider/model choices; it does not mark task acceptance. Focused native C++ tests cover Web-OFF silence, region and request routes, remake identity, cancellation, provider-listing entitlement claims, offline SRT output, Unicode, timestamp preservation, provenance, no-overwrite behavior, and invalid input. Kodi bridge Python tests cover local playback ownership for subtitle loading. A host without CMake/Qt cannot execute the C++ test target; VM/installed acceptance remains deferred, not a prerequisite for implementing the code.
